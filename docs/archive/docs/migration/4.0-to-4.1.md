# Migrating from Aura3D 4.0.x to 4.1

4.1 is additive for almost everything. This page lists the behaviour that changes, why, and what to do. Items are ordered by how likely they are to affect a shipped route. See [`docs/whats-new-4.1.md`](../whats-new-4.1.md) for the new features.

## Quick checklist

1. Replace imports of the ten deprecated `@aura3d/engine/*` subpaths (table below). They keep working in 4.1 and are now planned for removal in **5.0.0**, not 4.1.0.
2. If you call `createGame` from `@aura3d/engine/game`, the real game kit now starts without `qualityRebuild: { flags: ["game"] }`. If you relied on getting the stub there, opt out (below).
3. Look at any scene with directional (sun) shadows. They are lighter and tighter now.
4. If you called `setUniform` on a model node or passed `scene({ ... })` options, read the two items on those below.
5. If you carry workarounds from 4.0 (see "Workarounds you can delete"), remove them one at a time and check the frame.

## Behaviour changes

### `createGame` from `@aura3d/engine/game` turns the game lane on

Before: it returned the headless stub unless you passed `qualityRebuild: { flags: ["game"] }`. Now importing from the `./game` subpath is itself the opt-in (the `A3D_QR_GAME` lane defaults on there). Passing `flags: ["game"]` still works and changes nothing. To turn it off, in this order of precedence:

1. URL: `?a3d-qr=-game`
2. Environment: `A3D_QR=-game` or `A3D_QR_GAME=0`
3. Options: `qualityRebuild: { flags: ["-game"] }` turns off only the game lane. `qualityRebuild: { flags: "none" }` (or `["none"]`) turns off **every** quality-rebuild lane, not just the game lane.

### The root `createGame` stub is louder

`createGame` imported from `@aura3d/engine` (not the `./game` subpath) is still the headless stub. It now logs `CREATE_GAME_STUB` once, naming `@aura3d/engine/game`. Switch the import.

### `handle.setUniform` on a model node no longer throws

Without a custom material it is a once-per-uniform `MODEL_SETUNIFORM_NOOP` warning, because a GLB keeps its own materials. To drive a uniform on a model, give the node `material: material.custom(spec)`; with a custom material it writes as before. On a non-model node `setUniform` still validates its arguments.

### `scene(init)` builds what it says, and rejects unknown keys

Before: `scene({ children })` ignored its argument and returned an empty scene. Now `scene` accepts `children`, `background`, `camera`, `timeline` and `diagnostics`. Any other key, or a non-object argument, throws `invalid-scene-options`. If a route passed other keys (and quietly got an empty scene), fix the call: `scene().add(node)` still works.

### `material.custom` colour output

Unchanged default, now documented: a custom shader writes **linear light**, and the output stage sRGB-encodes it (and the default ACES operator tones it down), so a hex colour does not appear as authored. To get authored colours, `#include <colorspace_decode>`, wrap the output in `a3dSrgbToLinear(...)`, and set `output: { toneMapping: "none" }`. Any other tone-mapping operator still tone-maps custom colours. Custom shaders that call `pow` now get a total `pow` that never takes a negative base, so a rounding error can no longer produce NaN.

### Directional shadows

The receiver depth is clamped to [0, 1] in every directional sampler. Large receivers (ground planes) no longer shadow far beyond the caster's footprint. If you turned sun shadows off, or darkened lighting, to hide the over-dark ground, undo that and compare the frame.

### `instances.mesh` and `batched.mesh` apply texture maps

Before: the maps were dropped and surfaces rendered white. Now the same textured upgrade ordinary primitives get applies. Two things to check:

- A `texture.data` handle used as a base-colour map must declare `colorSpace: "srgb"`; binding validation rejects a linear base-colour texture.
- A multi-geometry `batched.mesh` drew nothing unless `qualityRebuild.flags` enabled `tiers.batching`. Without the flag it now falls back to per-geometry instancing (`fallbackReason: "tiers-batching-off"`). Enable the flag if you want the packed multi-draw route.

### Zero instances and empty geometry are valid

`instances.<primitive>` and `instances.model` with zero transforms used to throw (and a zero-length array threw `INSTANCING_CONTRACT` inside the render pass, blanking the frame). Zero instances now skips the node and reports `INSTANCES_EMPTY`. Empty `points` and `lines` report `GEOMETRY_EMPTY`; a geometry `drawRange` of count 0 draws nothing. A one-point polyline is still an authoring error. If you guarded these cases by hand, you can drop the guard.

### Repeated `model()` nodes share decoded textures

N nodes of one GLB now decode and upload each image once (a ref-counted cache keyed by asset url or id, sha256 and decode options). Geometry buffers are still per node. To opt out of the cache for a node created through `createTypedGLBActor`, pass `shareTextures: false`; `cloneSkinned` keeps its own cache.

### Audio: the cue bank mute key

`createCueBank(...).install()` now toggles mute on the mute key even when no `onMuteChange` callback is passed. Before, the toggle was skipped without a callback.

## Deprecated subpaths: removal moves to 5.0.0

The ten deprecated `@aura3d/engine` subpaths are kept in 4.1.0 and still print a one-time deprecation warning. Their removal moves from 4.1.0 to **5.0.0**. Replace them at your pace:

| Deprecated import | Use instead |
| --- | --- |
| `@aura3d/engine/contracts` | `@aura3d/engine` |
| `@aura3d/engine/media-node` | `@aura3d/engine` |
| `@aura3d/engine/apps` | `@aura3d/engine` |
| `@aura3d/engine/rendering` | `@aura3d/engine/renderer` |
| `@aura3d/engine/rendering/production-runtime` | `@aura3d/engine/renderer` |
| `@aura3d/engine/rendering/webgpu` | `@aura3d/engine/renderer` |
| `@aura3d/engine/production-runtime` | `@aura3d/engine/renderer` |
| `@aura3d/engine/advanced-runtime` | `@aura3d/engine/renderer` |
| `@aura3d/engine/assets/browser` | `@aura3d/engine/assets` |
| `@aura3d/engine/workflows/production` | `@aura3d/engine/workflows` |

The replacements come from the `deprecated` table in `packages/aura3d-cli/data/aura.exports.json`. The warning text and that table's `removeIn` field read `5.0.0` as of 4.1.0.

Also prefer the public `@aura3d/engine` surface and its subpaths (for example `@aura3d/engine/scene` and `@aura3d/engine/math`) over importing internal packages such as `@aura3d/rendering` from app code.

## Workarounds you can delete

These were common in games ported to 4.0. Remove each only after checking the frame:

| Workaround | Why it existed | In 4.1 |
| --- | --- | --- |
| `qualityRebuild` flags that switch off post, compiler or fog lanes for a whole app | A post-processing bug on some ANGLE/Vulkan GPUs and look tuning | Run on engine defaults and install the safety net instead (`installSafetyNet`) so a black frame steps down on its own. |
| Rewriting the page URL's `a3d-qr` to force flags | Same | Remove; pass options explicitly. |
| `qualityRebuild` nested inside `renderer` | A misplaced option the engine ignores | It belongs at the top level of the `createAuraApp` options. Moving it can switch features off or on, so test the frame. |
| `window.__AURA_PORT_MODULES__ = [port]` and namespace imports in wrappers | Self-registering modules were tree-shaken from production bundles | Plain `import "../../../examples/<game>/main"` now survives; the root `sideEffects` allowlist covers `./examples/**`, `./apps/**` and `./templates/**`. |
| Hand-written model modules (url, sha256, `?models=0`) | The production bridge drops untrusted models | `defineModelAssets`. |
| Guards around empty instance arrays | They threw | Not needed. |
| Hand-rolled `window.__AURA_<GAME>__` hooks and accumulator loops | No public kit | `installQaHooks`, `createFixedStepLoop`, `readQaParams`, `createCountedRng`. |
| Hand-rolled Web Audio cue code, one `AudioContext` per file | No synth kit; the repo forbids a second context | `createCueBank` on the shared `AudioContextManager`. |
| `instances.custom` used because `instances.mesh` lost textures | The textures bug above | `instances.mesh` / `batched.mesh` work again. |
| Per-port copies of hash, noise, safe-math and fog GLSL | No chunk library | `#include <a3d_noise>`, `<a3d_math>`, `<a3d_fog>`, ... |
| Per-game scatter and merge code | No planner | `scatterAlongPath`, `scatterInArea`, `mergeStatic`. |

## Apps and templates

- Templates that pass `qualityRebuild: { flags: ["game"] }` keep working unchanged. New routes can drop it when they import from `@aura3d/engine/game`.
- `@aura3d/engine/game` is published as a subpath of the root tarball. There is no separate `@aura3d/game` package to install (that package stays private).
- `@aura3d/debug` provides the safety net. Wire it in production routes only behind the `safety` option; it is inert by default.
- Meshy and other generated assets: admit them with `aura3d assets import-meshy --into <dir> --prefix <game> --name <role>` (isolated mode), and track spend with `aura3d meshy ledger`. See [`docs/api/cli-asset-tools.md`](../../../api/cli-asset-tools.md).

## Not changed

The `material.custom` colour contract, the default tone mapping, the default WebGL2 backend and the public `createAuraApp` options are unchanged, and the changes on this page add or rename no package.
