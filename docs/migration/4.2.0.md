# Migrating to 4.2.0

Version: 4.2.0

## The hosted asset index is retired

The hosted, federated asset index (a Cloudflare Worker, a D1 database and an R2 bucket) was never a dependable feature: its Worker was not deployed and published CLIs fell back to a small starter pack. It is removed, and its cloud resources are deleted. Asset discovery now runs at build time through the CLI, over open, licence-clear sources.

Removed from `@aura3d/asset-index` (runtime): `createAuraIndexAdapter`, `INDEX_STORE_SCHEMA`, `IndexStore`, `refreshIndex`.

Removed from `@aura3d/asset-index` (types): `AuraIndexAdapterOptions`, `IndexStoreFile`, `RefreshOptions`, `RefreshResult`, `WritableAssetIndex`.

What to use instead:

- `aura3d assets resolve "<need>"` decides per need: a project asset, an open CC0 source (Poly Haven, ambientCG), Meshy (only with `--allow meshy` and a budget), or a ready-to-paste procedural recipe built from primitives. Every file it produces is admitted with a sha256, provenance and licence, then typed with `model(assets.x)`.
- `aura3d assets search` and `aura3d assets pull` keep working over the open sources.
- The ranking, profile and open-source adapter exports of `@aura3d/asset-index` are unchanged.

If you used `createAuraIndexAdapter` or `IndexStore` to read or build your own index, keep your own copy of that code: nothing in Aura3D serves or refreshes a hosted index any more.
