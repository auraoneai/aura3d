## Decisions

1. `?look=original` keeps today's scene byte-for-byte (`addOriginalAtmosphere` + the old platform loop); the diorama is the default.
2. The predecessor's interim adapter `art/engineCompat.ts` was dropped: every GU47 API it wrapped is merged.
3. The art direction imports `GameArtDirection` type-only (vitest resolves `@aura3d/engine/game` by prefix, so `@aura3d/engine/game/art` does not load there); `defineArtDirection` runs in the unit test.
4. Heat shimmer is removed and re-added on every world mount (not toggled with `enabled`), so a world swap can never leave it on outside w4.
5. Banners and fans leave the instanced prop classes to become runtime nodes (AN1 needs per-prop motion); the leaf pads stay one instanced draw and bob as a whole node (instance transforms are world space).

## Blind-panel fix pass (2026-10-31)

Blind panel (3 judges, verify2 frames vs 4.6.2): w4 and w6 better; academy, w1, w2, w3 and w5 worse 0/3/0 (green-grey or
beige haze over the frame, a flat murky sky, miniature depth of field blurring the course, heavy vignette, banding on the felt
floor, a backlit Pip; w5 also had blown-out bloom on Pip).

Decision: the look is chosen once at boot for the whole game (`LOOK_MODE` feeds the HUD theme, fonts, camera framing and the
runtime presentation; every world swap goes through `setScene`, and the diorama's app-level state (output preset and exposure,
atmosphere fog override, w4 shimmer pass, DOF focus) has no verified reset path back to the original look). A per-world switch
could not be proven within the deadline, because the capture rows boot one world each and never capture a swap. Five of seven
worlds were not better, so the whole game now defaults to its 4.6.2 look (5e0021415): `lookModeFromSearch` returns `original`
unless the URL says `?look=diorama` (the diorama stays reachable for phase 3). w4 and w6 lose their better diorama frames by
default. Phase-3 item: a per-world look (w4/w6 diorama) with a verified diorama-to-original reset on world swap.

The 4.6.2 path itself had regressed on the current engine. The first capture of the new default (g06bp3, picassostagingacr,
academy and w1; the Premium registry's firewall refused the runner IPs twice, g06bp/g06bp2) showed a flat navy (#1e4d78) wall
where 4.6.2 drew a light-blue sky. The game code is the same as v4.6.2, so the cause is engine commit 9001eb1f8 (GU47 E-A, a
deliberate default change): a colour `background` override on `looks.preset` now emits the look HDRI with `background: false`.
The original path passed `background: skyColor`, and in 4.6.2 that HDRI was the sky. Fix (f8edcb5a1): the original path no
longer passes the override, so the HDRI is drawn again. `original-sky.test.ts` checks that every non-diorama world emits its
look HDRI without `background: false`. **Cross-lane note:** any game whose `?look=original` passes a colour `background` to
`looks.preset` has the same regression on the current engine.

### What changed

- **Per-world look switch** (65d18db73): `WORLD_DEFAULT_LOOK` in `src/game/looks.ts` picks the look each world opens in;
  `?look=diorama` / `?look=original` still force one look everywhere. `buildWorld` takes the world's own look, the camera framing
  follows the mounted world, and `presentation.worldMounted` follows `built.presentation.mode`. A 4.6.2-look world mounted after a
  diorama world gets the app-level state undone: output exposure back to 1 (the `Renderer.executeOutputPass` default), app fog
  cleared without touching the new scene's fog nodes, the w4 shimmer pass removed, trails/FOV kick/camera sequence ended
  (`presentation.test.ts` covers the diorama-to-original swap and an original boot that touches nothing). After the round-3 panel every
  world defaults to the diorama, so the 4.6.2 look stays reachable through `?look=original`.
- **Live sky reset** (dc3f64a0c): the engine copies a mounted scene's sky node onto the live atmosphere and never clears it
  (`ProductionEffectSystem.rebuildSkyFromScene`), so after a swap the previous world's sky kept drawing. In round 1, w4 and w5 showed
  w1's sky dome as a grey wall. A world with no sky node of its own now calls `atmosphere.setSky(null)`.
  **Engine handoff (E-G):** clear the live sky on `setScene` when the new scene has no sky node.
- **Daylight worlds (academy, w1, w2, w3)**: pure-sky HDRI drawn as the sky at EV 0 (`hdriSky`; academy/w1/w3
  `autumn_field_puresky` at different rotation and intensity, w2 `industrial_sunset_puresky`); no colour backdrop and no gradient dome
  (round 1: gradient domes under the diorama exposure blew out to a flat white wall); fog density about 0.001-0.0014 with max opacity
  0.1-0.16 (was 0.004-0.006 and 0.75-0.82); no miniature lens (`lens: "none"`); key moved behind the lens at 40-50 deg (Pip was
  backlit); key 2.8-3.0; vignette 0.05-0.06; brighter lawn felt.
- **w5**: daylight-outdoor post preset (the film preset bloomed Pip out), EV 0.9, matte honey-stone floor instead of glazed
  ceramic (floor glare), thin fog, no lens, vignette 0.1.
- **All worlds**: felt nap at scale 180 and strength 0.07 (the stock fabric normal tiled into grid bands across the big tops); felt
  sheen 0.35; key shadow bias 0.0015 and normal bias 0.14. Miniature lens (now only in w4 and w6): f/4 with a 2 px cap (was f/2, 4 px).
  w4: key 1.4, vignette 0.14. w6: EV 1.35, vignette 0.12 (458aa5815).
- **Kits**: the E-I crop contract is installed through `installQaHooks("qa", ...)` (`window.__AURA_QA__` keeps `crops`); the kits
  warning is gone.
- Art direction: `environment: { hdri: "autumn_field_puresky", background: "hdri" }`. That HDRI is no other live game's primary sky,
  so look-identity stays clean. w2 avoids `kloppenheim_06_puresky` (aura-links-3d's primary) and `belfast_sunset_puresky` (aura-hoops-3d).
