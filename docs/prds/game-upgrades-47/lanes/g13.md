## Decisions

1. No `workbench-night` look exists in E-A's merged set, so DD47-E1 is hand-built (no `looks.preset`): a look preset
   always emits a shadowed directional key, which would be a second shadow caster next to the desk-lamp spot.
2. `?look=original` is not added: dot-dash-3d is an app game, not a port, and E-I's targets for it are `?maze=` only.
3. Glowing materials that are light sources in the fiction (LED lenses, vents, lit traces, gems, halo, door, beam) are
   `practical: true`; the board, chips, pins and sentries carry no emissive at all, so the audit's `emissive-fill`
   rule is clean.
4. The trace signature uses an instanced overlay pool rather than a `material.custom` slab: one extra draw, no texture
   memory, and it works with the merged E-D instance-colour targets; the baked maps remain the M1 follow-up.
5. The run intro plays only when `score === 0 && dotsEaten === 0 && boardsCleared === 0`, because respawns also pass
   through READY.
6. Gameplay is untouched (PRD D8): every new value reads `st` (mode, positions, events) and nothing writes it;
   `sim.test.ts` (19 tests) passes before and after.

7. DD47-M1 does not use a `material.custom` slab: the author lights chunk (`a3d_lights`) shadows only the
   directional key, so a custom slab would lose the desk-lamp PCSS spot's chip-wall shadows (DD47-L1). The baked
   maps go on the existing `material.pbr` slab instead, as live canvas textures. A textured primitive keeps the
   `TexturedPBRMaterial` built at mount (a later `setMaterial` only replaces the scalar fallback), so the maps are
   repainted in place (`needsUpdate`) and the slab's roughness and clearcoat stay the mount board's; no roughness or
   metal map is bound because the engine copies those into a metal-rough composite at mount. The base colour factor
   is white, so the first frames before the async texture upgrade may show a white slab (check in phase 2).
   Bake cost ~45 ms at 512 x 392 in node (x4 at full size), once per board change. Texture memory: 3 RGBA8 maps
   with mips, ~12.8 MB at 1024 x 784 (desktop) or ~3.2 MB at 512 x 392 (phones / coarse pointer); the engine tier
   is not known when the scene is built, so the size follows the viewport.
8. The six LUTs are procedural (not generated assets), served by URL (`colorGrade({ lut: "/luts/..." })`) rather
   than admitted into `aura.assets.json`, matching how the HDRI is referenced.
