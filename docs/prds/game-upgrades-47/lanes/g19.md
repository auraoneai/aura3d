### Root cause of the judges' defects

Phase 2's "dark overhead beam" and "hard bright patch next to the drone" were not look problems. Before the first sim step, `Vehicle.position` is still (0, 0, 0): `updateVisual` runs only inside `race.frame`. So the menu backdrop (the steady-state capture) drew the drone and the chase camera at the world origin, directly under a gantry arch and beside a centre dash, not on the grid slot (s = length - 25, x = -10). The 4.6.2 frame has the same bug. The twilight look now draws the menu from the grid slot through a read-only view of the player (`menuPlayer` in `world.ts`); the sim's player is untouched (PRD D8). `?look=original` keeps the 4.6.2 menu frame value for value.
