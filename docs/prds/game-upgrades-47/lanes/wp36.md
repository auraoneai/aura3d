### Parent-account rule (Meshy task ids are per account)

A Meshy task id only works on the account that created it. Kiro Prism `84ff65c` (live: `/health` `deploy_source_commit`) resubmits rigging, retexture and remesh by `model_url` on a funded key; animations (`rig_task_id`) and refines (`preview_task_id`) stay on the parent's account and answer HTTP 402 `parent_key_exhausted` when it is drained. The pipeline therefore:

- submits every rig with the parent's GLB URL (`--model-url`, read fresh with a free `get` of the refine task) or the local source GLB, never `--input-task-id`; retextures already use the local GLB;
- on an animate refused that way (or a bare `503 quota_exhausted` on the pinned call), drops the clips made on the old rig, re-rigs the character from the rig row's input (refine GLB URL or source GLB; for `crownTauntF*` the old rigged GLB) on a funded key (~5 credits) and animates on the new rig (~3 per clip); outputs go to `<key>/rerig-<n>/` and `<key>/clips-r<n>/`;
- on a refine refused that way, starts a new preview (lands on the fullest key) and refines it (~30);
- caps chain restarts at 2 per row (`chainRestarts` in the row state), then defers the row 30 min;
- treats `parent_key_exhausted` / `quota_exhausted` / `busy` refusals as no-charge (`failed`) in the ledger.
