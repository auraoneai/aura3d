## Blockers and findings

- **Usable Prism pool is far below the plan.** Prism reported 9,747 credits, but 12 keys (`meshy-06, -09, -11, -12, -16, -18, -21, -22, -24, -26, -27, -29`, 7,890 credits, all resetting 2026-11-01T00:00Z) answer HTTP 402 although they report a balance; Prism parks them after the refusal (and shows 0 for three of them). Usable credits at the run start were about 1.6k-3.1k, so the run stops early inside P1 (estimate 12,682 for P1). Restart after the 2026-11-01 reset (or start with `--wait-for-credits`).
- Prism tries only a few keys per call, so the first previews were refused (`503 quota_exhausted`) while good keys still had credits; the script now re-checks the pool and retries (bounded streak of 8), and settles such refusals as `failed` (no task existed, 0 credits).
- Text-to-3d props come out above the role vertex budget after `assets optimize` (the default `--error 0.05` stops simplification early, e.g. 31k tris for a prop); every result still passes its profile's triangle limit. Wave-2 lanes may re-run optimize with `--max-verts`/`--error` per scene budget.
- Humanoid text-to-3d bases admit with the blocker `humanoid-structure: no skeleton` until their rig row runs; vehicle retextures report the wheel-separation blocker. Both are candidate results to report, not pipeline failures.
- Animate rows `crownTauntF1..F6` reuse rig tasks from an earlier session; they work only while Prism still holds those task-key affinities.
