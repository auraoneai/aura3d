## 0. The facts that matter most for a games-look PRD

1. **Flags decide what renders.** `R:contracts/flags.state.ts:18-46`: default-on lanes are `A3D_QR_CORE, LIGHTING, POST, MATERIALS, ASSETS, ANIMATION, VFX, CAMERA, COMPILER`. Dev (off) lanes: `A3D_QR_GAME, WORLD, TIERS, WEBGPU, LOOKS, STRICT`. Sub-flags are read with plain `flags.on(name)` (`E:contracts/flags.ts:216`, registry gate `R:contracts/core.ts:70,131`), so a sub-flag is off unless a source sets it. The only parent-defaulted sub-flags are `A3D_QR_WORLD_{TERRAIN,WATER,BIOME}` (`E:contracts/flags.ts:61-63`, and WORLD itself is dev). PRD-02 lighting sub-flags (`A3D_QR_LIGHTING_CSM/PROBES/CONTACT`) are kill switches, on unless set off (`R:passes/Prd02SubFlags.ts:9-24`).
   Off by default, and so not seen by any player: `A3D_QR_VFX_SKY` (real sky), `A3D_QR_VFX_FOG` (height fog), `A3D_QR_VFX_VOLUMETRIC` (froxel fog), `A3D_QR_VFX_DECALS` (GPU decal batch), `A3D_QR_MATERIALS_TRANSMISSION`, `A3D_QR_MATERIALS_KTX2`, `A3D_QR_POST_VELOCITY_MRT` (per-object velocity), `A3D_QR_ANIMATION_SKINNED_SHADOWS` (deformed skinned depth), `A3D_QR_TIERS` (live quality tier), `A3D_QR_WORLD*` (terrain, water, biome, grass).
   Games opt into lanes through `qualityRebuild: { flags: [...] }` on `createAuraApp`/`createGameApp` (`E:contracts/flags.ts:223`). Live games only pass `["game"]`, `["game","animation"]` or `["game","materials"]` (for example `apps/showcase-aura-hoops-3d/src/main.ts:861`, `apps/showcase-dot-dash-3d/src/main.ts:81`). No game turns on a visual sub-flag.
2. **Every look is built from 3 HDRIs.** `looks.preset` lowers to the v0 expansion only (`E:agent-api/looks/lookNodeHandler.ts:22` `lowerLookNodeChildren` forces `expansion: "v0"`). The v0 table (`E:agent-api/looks/lookPresets.ts:110-370`) uses `autumn_field_puresky_1k` for outdoor-day, overcast and alpine-snow, all at the same sun (elevation 48, azimuth 35); `kloppenheim_06_puresky_1k` for golden-hour; `studio_small_08_1k` for every interior and studio look; and no HDRI for night-city, polar-night, space, underwater and neon-arcade (procedural "neutral" fill instead). The checkout carries 17 HDRIs in `fixtures/environment-corpus/hdri/` and 8 in `assets/library/hdri/`.
3. **Looks drop half of what they declare.** `E:agent-api/looks/looks.ts:334-343` emits `effects.colorGrade` with `contrast`, `saturation` and `exposure` only; the preset's `grade.temperature` (for example golden-hour 0.25, polar-night -0.2) is never emitted. The preset's `post` id (`cinematic-film`, `neon-night`, ...) is never applied by `looks.preset` (no `output.preset` child in `v0Children`, `looks.ts:278-360`). Bloom is a bare `effects.bloom()` (defaults intensity 0.35, threshold 0.7, radius 0.38; `E:agent-api/nodes/effects.post.ts:27-52`), identical for every look except a colour override.
4. **Look overrides have five knobs:** `sun {azimuthDeg, elevationDeg}`, `exposureEv` [-2,2], `fogDensityScale` [0,3], `accent`, `background` (`E:contracts/looks.ts:12`). A game cannot change a look's HDRI, grade, key colour, rim light or post preset through the look. Nine look-using games pass `fogDensityScale: 0` in at least one place (for example `apps/showcase-roadster-rush/src/main.ts`, `apps/showcase-dot-dash-3d/src/game/world.ts`, `examples/kid-goku-beyond-the-clouds-port/world.ts`), which removes the look's fog.
5. **Post runs on the v2 chain at a fixed "high" tier.** With `A3D_QR_POST` on, `E:agent-api/compiler/postprocess.ts:101` resolves the post tier to the authored tier or `"high"`; `A3D_QR_TIERS` is off, so `"auto"` never follows the device for post. At high: GTAO half-res 4 directions x 4 steps, god rays 48 samples, DOF half-res 1 ring, motion blur 8 taps, SSR "medium", bloom 6 mips, TAA off (MSAA 4) (`R:post/PostQualityTiers.ts:82-139`, `R:contracts/quality.ts:76-86`).
6. **Two post stages are declared but do not draw.** `S3-ssr` has no program in the v2 driver (header list `R:post/v2Stages.ts:6-21` names S1, S2, S4, CA, S5, S6, S7, S10b, S11, S12; no SSR shader in `R:post/shaders/`). The `.cube` LUT parses (`R:post/CubeLut.ts:25`) but S10b always binds the identity LUT with `u_hasLut = 0` (`R:post/v2Stages.ts:1218-1219, 1250-1252`). The HDR grade terms (`temperature`, `tint`, `lift/gamma/gain`, `shadows/midtones/highlights`) are mapped into the option bag (`E:agent-api/postBridge.ts:921-936`) and declared in `R:post/shaders/composite.glsl.ts:25-31`, but no code in `R:` sets `u_lift` or `u_whiteBalance` (rg over non-shader sources returns nothing), so they do not reach pixels. `contrast` and `saturation` do (receipt `evidence/receipts/effects-color-grade`).
7. **Usage across the 25 live games** (`docs/workflows/game-inventory.json`; tally script `/tmp/gu47/tally.mjs`, output `/tmp/gu47/tally.txt`): vignette 20, bloom 18, fog 17, `looks.preset` 14, hemisphere light 14, colour grade 11, explicit tone mapping 11, `material.custom` 12, AO 9, contact shadows 8, `environments.*` 8, `sky.*` 5, anti-alias node 5, HDRI file 3. **Zero games** use: `sky.dayNight`, `weather.*`, depth of field, SSR, volumetric fog / god rays, TAA, LUT, auto-exposure, outline, chromatic aberration, `output.preset`, `lights.lensFlare`, area lights, transmission. One game each: water (`water.` match in aura-links is its own layout field, not the engine builder), motion blur (aura-fc-3d), toon post (silt-and-signal-port), film grain (bunker-zero). Probes 2, decals 2.
8. **Brightness spread is wide.** `evidence/audit-fix/e5/wave2/sweep/table.md`: steady-state mean luma on 4.5.0 runs from 2.26 (aura-links-3d neonBay, a near-black frame) and 29.48 (dot-dash-3d) to 231.74 (aura-fc-3d uyuni); splat-rush-port has 25.83% clipped pixels. All 40 targets measured on 4.5.0 take the `hdr-msaa` path (3 more were not reached).

Games that kept a hemisphere next to an environment got brighter (dot-dash-3d +18%; per-game deltas `docs/audits/lanes/e2.md`, untracked in the main checkout).
