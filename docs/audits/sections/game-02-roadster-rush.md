## 02. Apex Overdrive (`roadster-rush`)

**Live:** https://aura3d.auraone.ai/apps/showcase-roadster-rush/ · **Source:** `apps/showcase-roadster-rush` · **Genre:** racing

**State:** The game loads and plays on production. The live probe ran on SwiftShader software GL in Prism and found no console errors and no failed requests (45 resources). Steering, crash to "Wrecked!", the saved best score, Space-to-restart and bolt pickup all worked. The frame is lit and varied: mean luma 83-85, 1-1.6% of pixels below luma 12, nothing clipped. The draw call count is high, 868-895 per frame (`__GAME__.getState().drawCalls`). The simulation is sound, but the renderer's fixed node pools are smaller than what the simulation contains. As a result the player meets traffic, sky cars, bolts and sign gantries that are not drawn, all Meshy traffic faces backwards, and the first run has no sound.

**4.5.0 impact:** 4.5.0 changed no game source; `git diff --stat v4.3.7 v4.5.0 -- apps/showcase-roadster-rush` shows only `package.json`. Engine changes do reach the game. `looks.preset("outdoor-day")` (main.ts:218) adds an AO pass, and AO now reads real depth, so the frame changes from a constant darkening to crease AO. Bloom runs on quality `auto`, which means fused `separable` bloom. The authored `lights.hemisphere` (main.ts:231) is still dropped because the scene has an HDRI environment (LIGHT-05); this matches 4.3.7. None of these changes broke the game live. No 4.5.0 frame of this route has been captured, though: the final screens date from 2026-10-25 (commit e62b5fd42), so the size of the AO and bloom change is unknown.

**Tests and evidence gaps**

- No test checks that the renderer draws what the simulation holds. Extract the slot assignment in `syncRoadsterWorld` as a pure function, replay seeds for 90 s, and assert that every vehicle, sky car, bolt and gantry within 120 m ahead has a node of its own type (covers RR-1, RR-2 and RR-4). The browser specs step frames manually and never reach the 20-60 s density where the pools overflow.
- There is no facing check for traffic (M15) and no check of `AudioContext.state` after the first keydown (RR-3, RR-5).
- No 4.5.0 frame exists. Recapture title, early, key-ramp, mid and results on the remote runner, and add this route to the steady-state luma harness with an AO-on/AO-off pair and a `?aura3d-render=production` bloom comparison (LIGHT-02, LIGHT-06, RP-05, RH-05).
- All existing captures are from software WebGL2; there is no real-GPU frame.
- RH-06: this page loads the shared 2.6 MB `aura-assets-BECYe7eh.js` catalog, many of whose URLs return 404. Switch to the per-app manifest.
- The probe saw one held KeyD move the car two lanes, although input.ts ignores `e.repeat`. This is likely a Prism key-hold artifact; recheck on a real keyboard.

**Dropped on verification**

- RP-04 (a bad `?aura3d-render=` value stops the mount): this is an engine-wide debug-URL issue with no game-specific effect, so it belongs in the release section.
- LIGHT-05 (hemisphere dropped): kept in the 4.5.0 impact note instead of the fix table, because the behaviour is unchanged from 4.3.7 and the fix is in the engine.
