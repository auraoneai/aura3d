## 14. Cross Hop (`cross-hop`)

**Live:** https://aura3d.auraone.ai/apps/showcase-cross-hop/ · **Source:** `apps/showcase-cross-hop` · **Genre:** platformer

**State:** The game loads and plays on production. In the Prism probe (SwiftShader software GL, `hdr-msaa` path), it autostarted Quick Play, hops moved one row per tap, the hawk death and HOP AGAIN worked, and there were no console errors or failed requests. Steady-state mean luma was 110.7 at about 12 s, with 0.5% of pixels dark, none clipped and 118 coarse colours, so the frame is lit and varied. The game is playable, but its run logic has several real bugs: coin inflation, score farming, an unwinnable drill, oversized train hitboxes, rail warnings that are not tied to the trains, and a stale look after restart.

**4.5.0 impact:** `git diff v4.3.7 v4.5.0 -- apps/showcase-cross-hop` is empty, so the release reaches this game only through the engine. The one change that matters: the night-city (Emberline, theme 3) and neon-arcade (Neon District, theme 4) looks now carry a neutral fill (`lookPresets.ts:171,189`, `{ preset: "neutral", intensity: 0.85 }`). That fill is only dropped next to an authored ambient light inside `scene().toJSON()` (`scene.ts:157`, the only caller of `dropShadowedLookFill`). Cross Hop's `swapLook` adds the look through `app.nodes.add` (`core.ts:646-647`), so in those two themes the fill, capped at 0.58 by `buildLookGroup` (`core.ts:259-264`), stacks on the game's `lights.ambient` 0.42. Nobody has captured or measured either theme on 4.5.0. Contact shadows, AO and bloom fusion apply but were not compared against 4.3.7. The upgrade guide `docs/upgrade-4.5.0/cross-hop.md:64` still describes the pre-fix `night` fill.

**Tests and evidence gaps**

- The tests cover lane generation only (`tests/lanes.test.ts`, 54 lines). Nothing tests `core.ts` scoring, coin banking, restart, drills, hitboxes or rail cycles, which is how CH-1 to CH-5 shipped.
- `screens/final` dates from d658eb2a1 (2026-10-25), before the last source commit c45022372 and before 4.5.0. There are no frames of Emberline, Neon District, a drill or the death card.
- The `crosshop` target in `tests/browser/game-luma-capture.spec.ts` captures theme 0 only, and no Cross Hop result is recorded anywhere. Capture `?theme=3` and `?theme=4` after a swap, on 4.3.7 and on 4.5.0, on the remote runner.
- Bloom fusion was never compared against `?aura3d-render=production` for this game (RP-05).
- The live probe saw `materials.textureBytes` grow from 114.3 MB to 126.9 MB (+11%) across two restarts in the same theme. Run a 20-restart loop to tell lazy loading from a leak.
- No draw-call or frame-time numbers are in evidence (checklist line 40). The live probe's figures come from SwiftShader only.

**Dropped on verification**

- The live probe's double hop from one 200 ms ArrowUp press: dispatched keydown/keyup pairs moved exactly one row each, so this comes from how Prism delivers a held key, not from the game.
- The live probe's note that `main.ts:79-81` drops the sim's 0.14 s window: both values are 140 ms today, so nothing goes wrong; this is a code smell only.
- The about 1 fps rAF rate in the probe: this is a SwiftShader artifact, not a game defect.
