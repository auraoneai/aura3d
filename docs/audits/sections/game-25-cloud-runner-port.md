## 25. Cumulus Dash (`cloud-runner-port`)

**Live:** https://aura3d.auraone.ai/apps/cumulus-dash/ · **Source:** `apps/showcase-cloud-runner-port` (3-line shim mounting `examples/kid-goku-beyond-the-clouds-port`) · **Genre:** platformer

**State:** The game loads and plays on production with 0 console errors and 0 failed requests. The probe ran in the Prism cloud browser on SwiftShader software GL, using the hdr-msaa path at quality `auto`. Menu frames read mean luma 121-132 and in-play frames 155.4, with 0% black and 0% clipped pixels. Steering, Play, the result card and Enter-to-retry all work. A real run ended correctly after 3 gap falls. Two logic bugs remain. Dying on an obstacle soft-locks the run. "Run it again" after a win restarts near the finish with every pearl kept. The scene is heavy for a lane runner: 164 draw calls, 647k triangles and about 252-333 MB of GPU memory.

**4.5.0 impact:** The app folder changed only in its `package.json` version. The engine changes do reach the game. In 4.3.7 the authored `sky-fill` hemisphere light was turned into a direct spot proxy (`observations.ts` fallthrough in v4.3.7). Commit 5f0fd854f now drops it as a direct light (`renderer.ts:188` `hemisphereAsEnvironment: true`, `observations.ts:333`). Because the look preset's HDRI exists, only the neutral-room source (`environment.ts:561`) reads hemispheres, so the light now contributes nothing. Live diagnostics show `lightsEvaluated 2` with `hemisphere:false`. The brightness change was never measured. The 4.5.0 exposure-parity record has identical before and after means (172.2815437219224) and a 404 on both. The real-depth AO change has no effect here, because the look's SSAO pass is dropped for missing normals. Bloom fusion (`separable`) was not compared against the production chain for this game. The upgrade guide says "No change needed" and still has 8 open checkboxes. This needs a measured capture before anyone calls it fine.

**Tests and evidence gaps**

- The unit tests (`tests/unit/kid-goku-beyond-the-clouds-port/game.test.ts:132`) cover death only by a gap fall. Nothing covers obstacle death at 1 heart (CR-1), retry after a win (CR-2), blur or visibility pause, or the touch handler. Pause also ignores the `falling` and `finale` phases (`game.ts:96`).
- The exposure-parity record for this game is void. Before and after are both 172.2815437219224 with a 404 (`evidence/exposure-parity/frames/scenes.json`). Steady-state luma at fixed `place()` points (60, 520, 1100, 1420, 1700) on 4.3.7 and 4.5.0 is needed, with and without the hemisphere fix (LIGHT-02, LIGHT-06).
- There is no per-game comparison of fused bloom against `?aura3d-render=production` (RP-05).
- The final screens (`evidence/kid-goku-beyond-the-clouds-port/screens/final`, last commit 2026-10-25) predate the boulder grounding fix and 4.5.0 (RH-05). They are 640x360 only. They contain no real won or lost result card (results.640x360 is a forced `place(1000000)` cutscene), and no capture emulates `pointer: coarse`, so the touch controls are never shown.
- `docs/upgrade-4.5.0/cloud-runner-port.md` has 8 unchecked items and says "No change needed" without a render (RH-04).
- Nothing has run on a real GPU. All evidence is SwiftShader.

**Dropped on verification**

- C3 as a P1 "regression": downgraded to P2 and merged with LIGHT-05 as CR-3. The light did change (a spot proxy in 4.3.7, dropped in 4.5.0), but the 4.3.7 proxy was itself a mis-aimed spot and the visible size of the change is unmeasured. LIGHT-05's claim that the behaviour "matches 4.3.7" is wrong for this game.
- C8 split: the keyboard-only hints became CR-9 (downgraded to P3 because the touch buttons are labelled) and the sound toggle became CR-E4.
- C10 split: the hidden boot error became CR-7 and the missing warmPrograms became CR-E3 (P3, because no hitch was measured).
- RP-04 (a URL typo stops the mount): an engine-wide debug switch, not specific to this game. It belongs in the release section.
- Probe note that the `main.ts:1-4` header reverses the names: cosmetic comment only, not an audit item.
