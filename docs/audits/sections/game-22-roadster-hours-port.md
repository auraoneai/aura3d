## 22. Saltwind Highway (`roadster-hours-port`)

**Live:** https://aura3d.auraone.ai/apps/saltwind-highway/ · **Source:** `apps/showcase-roadster-hours-port` · **Genre:** racing

**State:** The game loads and plays on production. The live probe (Prism, SwiftShader software GL) saw no console errors and no failed requests. The render path was `hdr-msaa` with 121 draw calls, 9 programs compiled and 0 failed. Steady-state luma held at mean 78.6 to 79.0, about 6% below 12, 0% clipped and 73 colours, at both 3 s and 12 s. Driving, steering, pause, a full autopilot finish (59.65 s, Silver), the results card and restart all worked. Health is degraded: two P1 bugs affect players, R recovery fires about 12 times per tap and there are no touch controls, plus a set of audio, coaching and copy gaps.

**4.5.0 impact:** The game's source did not change. The release only bumps the version in `apps/showcase-roadster-hours-port/package.json`. No `quality` option is passed (`examples/roadster-hours-port/main.ts:337-342`), so the game resolves to quality `auto`. Under `auto`, 4.5.0 turns on separable bloom fusion and shadow-cascade skipping for this bloom-plus-sun-shadow scene. Live luma looks normal, but neither change has been compared against 4.3.7 or `?aura3d-render=production` for this game. The deprecated `renderer.qualityProfile: "production"` (`main.ts:339`) no longer selects the pipeline and only logs a warning. Nothing is broken, but the release effect on this game is unmeasured.

**Tests and evidence gaps**

- No 4.5.0 capture of this game exists. `screens/final` dates from 0d965903c (2026-10-25), before v4.5.0. Neither `RESULTS-4.5.0.md` nor PRD-3 mentions it. Needed: `?capture=1` against `?capture=1&aura3d-render=production` on the remote runner to measure bloom fusion (RP-05), and a 4.3.7-vs-4.5.0 steady-state luma row in `game-luma-capture` (LIGHT-02). Then refresh the screens and posters (RH-05) and close the per-game upgrade guide checks (RH-04).
- Instanced scenery (palms, pines, boulders) picks one shadow cascade from the node centre. Spread-out instances can fall outside that cascade and render unshadowed (SI-1, an engine issue that predates 4.5.0). Check it in the same capture.
- The browser spec has one test (`tests/browser/roadster-hours-port.spec.ts:54`). There are no unit tests for `keyboardInput`, pause, restart or the step-to-results flow, which is why C1 and C4 shipped.
- A typo in `?aura3d-render=` or `?aura3d-bloom-fusion=` stops the game from mounting (RP-04, engine-wide).
- The live probe ran on SwiftShader at about 6.5 real fps, and the countdown ran in slow motion because each frame is capped at 0.1 s. There is no real-GPU frame-time number.
