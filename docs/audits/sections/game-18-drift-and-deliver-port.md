## 18. Gridlock Courier (`drift-and-deliver-port`)

**Live:** https://aura3d.auraone.ai/apps/gridlock-courier/ · **Source:** `apps/showcase-drift-and-deliver-port` · **Genre:** racing

**State:** The production page loads clean in the Prism cloud browser: 0 console errors, 0 failed requests out of 53 resources, all 94 asset entries ready, 20 programs compiled with 0 failures, 112 draw calls, render path `hdr-msaa`. The renderer was SwiftShader (software GL) at about 0.2 fps, so the probe proves correctness, not speed. Steady-state frames stay lit and varied: mean luma 110.3 to 110.4, 0% dark, 0% clipped, 88 to 90 colours at 175 s, 359 s and 1194 s. Driving works (holding W moved the car from z -120 to -107 and the HUD read 32 km/h), and so do pickups and the streak (score 0 to 10, '1 / 174'). The app folder is a 3-line shim over `examples/drift-and-deliver-port`. The deterministic sim passes its 130 unit tests. The game is healthy but incomplete: it has no touch input, no end state, and the canvas does not follow window resizes.

**4.5.0 impact:** 4.5.0 changed no game source, only the `package.json` version. Engine changes still reach the game, because `createAuraApp` (`examples/drift-and-deliver-port/main.ts:454-461`) sets no `quality`, so the game runs on `auto`. The live diagnostics confirm `{path:'hdr-msaa', quality:'auto', bloomFusion:'separable'}`. That turns on separable bloom fusion for the 0.35 bloom (`look.ts:181`) and cascade skipping for the 2-cascade 2048 px sun shadow (`look.ts:176`). Neither has been compared against `?aura3d-render=production` on this game. The 1.7-intensity hemisphere light (`look.ts:177`) sits next to `environments.hdri` (`look.ts:175`), so the engine still drops it, the same as in 4.3.7 (LIGHT-05). The heal ladder's `no-env` rung (`packages/debug/src/safety/blackFrame.ts:23`) removes the HDRI, so lighting on that rung now depends on the 4.5.0 lights-only path; that rung has never been captured. AO is opt-in (`?ao=1`, `look.ts:179`), so the real-depth AO change does not affect default frames. I found no regression in code, but no post-4.5.0 capture exists. The newest final screens come from build `0d965903c`, which is older than four later game fixes: the minimap fix `cb2933126`, the hatchback hero car `4507f5f19`, the cue bank and black-frame guard `c45022372`, and the road mapping fix `2073d570a`. I checked each one with `git merge-base --is-ancestor`, and none is in that build.

**Dropped on verification**

- C7 and C8 were merged into the evidence-gap bullets above. They describe missing receipts, not defects. I also dropped C8's claim that degraded heal rungs are 'darker than before': with the HDRI removed, the scene may switch to the path where the hemisphere light contributes, so the luma could move either way, and nobody has measured it.
- RP-04 (a typo in a debug URL switch stops the mount) is an engine-wide robustness item. It is reported in the release section, not per game, and no player reaches it.
- LIGHT-05 and LIGHT-06 are covered under 4.5.0 impact. LIGHT-05 behaves the same as 4.3.7 on this game. LIGHT-06 does not apply to default frames, because AO here is opt-in (`?ao=1`, `look.ts:179`) and the game uses no look preset.
