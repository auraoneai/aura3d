## 13. Glint Courier (`dot-dash-3d`)

**Live:** https://aura3d.auraone.ai/apps/showcase-dot-dash-3d/ · **Source:** `apps/showcase-dot-dash-3d` · **Genre:** arcade

**State:** The game loads and plays on production. A Prism probe (SwiftShader software GL) logged no console errors and no failed requests. It measured 39 draw calls on the `hdr-msaa` path and a steady-state mean luma of 30.0 at 1440x900, with 9.2% of pixels below 12 and none blown. That is a dark neon board, not a black frame. Movement, dot eating, sentry catches, lives and the R reset all worked. The run loop has two serious defects: after game over the card never closes, and clearing the last board ends on a frozen screen with nothing on it. The card art on the site is also still the pre-rework arcade clone.

**4.5.0 impact:** The scene authors `lights.ambient`, so 4.5.0 drops the `neon-arcade` neutral fill (`world.ts:111`). The lights-only branch now adds the authored `lights.hemisphere` (`world.ts:112`) to the ambient. The upgrade guide measured steady-state luma at 25.0 on 4.3.7 and 29.5 on 4.5.0, an 18% rise (`docs/upgrade-4.5.0/dot-dash-3d.md:27`). The live 30.0 agrees with that. The board still reads correctly, so the rise needs only a by-eye decision, not a fix, but the CHANGELOG claim of "within about 5%" is wrong for this game. The look's AO pass is dropped live (`ssao:normals` missing), so the AO real-depth fix has no effect here. Bloom, vignette and transparent materials keep the game on the HDR path, so the new direct path does not apply. Fused bloom (`separable`) is the default on this path and nobody has compared it per game. The shadow diagnostics disagree with each other (see DD-10).

**Tests and evidence gaps**
- The 998-line `sim.ts` has no unit tests. `tests/unit` has only the quickbar and rng-consolidation files for this game, and no browser spec reaches game over or win, which is how DD-1 and DD-2 went undetected. Add `tests/unit/dot-dash-3d/sim.test.ts` covering: a cleared board advances and keeps the score, three catches end in game over, chain scoring, wrap edges and fruit. Add a browser case that asserts the overlays.
- `apps/showcase-dot-dash-3d/evidence/captures/` is stale. It holds a failed capture, and `metrics.json` still uses the old title "Dot Dash 3D — Neon Maze Chase". Delete it or regenerate it.
- Nobody has compared fused bloom against the production chain for this game (RP-05). Capture `?capture=1` against `?capture=1&aura3d-render=production` remotely.
- Under SwiftShader the probe counted 56 frames in 5 s, each with dt 1/60, so the sim ran at about 0.19x real time. `__gameEvidence` has no sim-time field, so tooling cannot tell a slow sim from a stalled one. Add `simTime` to the evidence beacon.
- The `hf432-live-d2` "dot-dash dpr2" capture times out at 120 s, cause not isolated (`evidence/visual-regression-4.5.0/prd2.md:55`).
