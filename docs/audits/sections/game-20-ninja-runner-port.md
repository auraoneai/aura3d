## 20. Shadowstep Gauntlet (`ninja-runner-port`)

**Live:** https://aura3d.auraone.ai/apps/shadowstep-gauntlet/ · **Source:** `apps/showcase-ninja-runner-port` (game code in `examples/ninja-runner-port`) · **Genre:** action

**State:** The game loads and plays to the end on production. In the Prism probe (SwiftShader software GL, 1440x900) the page showed no errors and no failed requests across 65 resources. `diagnostics()` reported 93 draw calls, renderPath `hdr-msaa` with `bloomFusion: separable`, and 0 failed programs. Mean luma was 125.6 on the menu and 122.9 on the won screen, with 0% dark and 0% clipped pixels. The autopilot run reached `won` at 2,640 m with 74 defeated, a real KeyD press changed lane, and Enter restarted the run. Health is good. The main costs are a heavy first load (26.75 MB transferred) and a few gaps in pause and input.

**4.5.0 impact:** The release changed no game code. `git diff --stat v4.3.7 v4.5.0` touches only `apps/showcase-ninja-runner-port/package.json`. Rendering did change. `main.ts:423` passes `renderer: { mode: "production", qualityProfile: "production" }` and no `quality`, so 4.5.0 resolves quality to `auto` (`renderPath.ts:151-156`). That turns on separable bloom fusion and the unsampled-cascade skip, which the live probe confirmed (`bloomFusion: separable`). The high tier's `effects.ambientOcclusion` (`world.ts:235`) now reads real depth. No frame of this game has been taken on 4.5.0: every file in `evidence/ninja-runner-port/screens/final` dates from 2026-10-25. The live frames look correct, but the size of the shift from 4.3.7 is unmeasured. The 4.3.0 shadow-fit opt-in (S-01) dates from 4.3.2 (commit 3405d2082), not 4.5.0.
