## 15. Craterline GP (`strange-orbit-port`)

**Live:** https://aura3d.auraone.ai/apps/craterline-gp/ · **Source:** `apps/showcase-strange-orbit-port` · **Genre:** racing

**State:** The game loads and plays on production with a keyboard. The live probe ran on the Prism cloud browser (SwiftShader software GL) and saw no console errors and no failed requests. The page used renderPath `hdr-msaa`, 115 draw calls and 41 assets ready. Mean luma was 85.4 on the menu and 76.9 while racing, with 0.2% of pixels below 12, so the frame is not blank. Restart works. The game has three problems a player hits: there is no touch input at all, every difficulty is easy to win, and 6th place awards a bronze medal. The app is a 3-line wrapper around `examples/strange-orbit-port/` (about 3,900 lines). That source did not change between v4.3.7 and v4.5.0; the only change is the version bump in package.json.

**4.5.0 impact:** The game code is unchanged, but the engine under it changed. First, `renderer: { mode, qualityProfile }` (examples/strange-orbit-port/main.ts:479) no longer picks the pipeline, so the game now runs on quality `auto` with separable bloom fusion and the shadow-cascade skip. Nobody has rendered or compared it in that mode. Second, the scene authors hemisphere, key and fill lights and has no `environments.*` node (world.ts:181-190; `rg environments examples/strange-orbit-port` finds nothing). In 4.5.0 such a scene loses the implicit neutral-room IBL. The custom-GLSL track, sky and islands compute their own light (shaders.ts:28-41) and are unaffected. The eight lit Meshy/catalog GLBs (riders, pylons, boulders, lander, observatory, moon rocks) lose their diffuse and specular fill. docs/upgrade-4.5.0/strange-orbit-port.md recommends `environments.studio`, and that change was not applied. The only number is a whole-frame menu luma that went from 55.6 to 54.4 (-2%, evidence/exposure-parity/README.md:48), and it mostly measures sky. The game is not broken by the release, but its lighting needs a measured region check and probably an environment.

**Tests and evidence gaps**

- Nothing has been rendered since 4.5.0. The last commit to evidence/strange-orbit-port/screens/final is 9e89ef082 (2026-10-25), and 4.5.0 shipped 2026-10-28. route-health.json is from 2026-10-23. The index posters predate the release too (RH-05).
- The game has no 4.3.7-vs-4.5.0 steady-state luma capture. Add the route `/apps/craterline-gp/` to tests/browser/game-luma-capture.spec.ts TARGETS and measure luma inside the rider region (LIGHT-01, LIGHT-02).
- Fused bloom (`separable`, on `auto`) has never been compared with `?aura3d-render=production` for this game (RP-05).
- The upgrade guide's checkboxes are open, and the guide says the GLB change was not rendered (RH-04).
- No browser spec drives a race by touch. The unit suite (131 tests) has no test of difficulty balance and no test of the medal-by-place mapping.
- Every browser run so far used SwiftShader. The game's fixed-step loop caps each frame at 0.08 s (main.ts:179-182), so on software GL the race ran at about 0.03x wall time. No real-GPU frame exists (tools/real-gpu/run.sh).
- A typo in `?aura3d-render=` or `?aura3d-bloom-fusion=` throws during mount (RP-04, engine-wide). This is not specific to this game.

**Dropped on verification**

- Code-audit C7's citation `README.md:44` was wrong; the claim is on line 42. It is kept as SO-6 with the corrected line.
- Code-audit C4's statement that "RaceEnd.medal allows null" is wrong: race.ts:125 is a non-null union. The fix in SO-2 includes widening the type.
