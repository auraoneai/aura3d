## 16. Chroma Roll (`splat-rush-port`)

**Live:** https://aura3d.auraone.ai/apps/chroma-roll/ · **Source:** `apps/showcase-splat-rush-port` · **Genre:** platformer

**State:** The game loads and plays on production. The live probe found no errors, no failed requests (38 resources), webgl2 on the `hdr-msaa` path, and all 28 assets `ready`. Splash, play and game-over frames had mean luma 191-197 and 0% dark pixels, with 21-32% at pure white because the scene uses `toneMapping: 'none'` (main.ts:212). Clicking to start, holding ArrowLeft to steer (x 0 to -1.06 in 1.5 s), Space to restart, and best-score persistence all worked. The probe ran on SwiftShader software GL at 0.8 fps, so its frame rates say nothing about real GPUs. The game code is in `examples/splat-rush-port`; `apps/showcase-splat-rush-port/src/main.ts` only mounts it. Overall it is playable, but three P1 defects need fixing.

**4.5.0 impact:** The game's only 4.5.0 commit is a version bump. The engine change that matters is "authored lights only" (`compiler/renderer.ts:152` passes `implicitFill: false`, and `compiler/environment.ts:172-179` returns preset `authored-lights`). This scene authors a hemisphere light plus two directional lights and no `environments.*` node (backdrop.ts:49-52), so its Meshy GLBs lost the neutral-room IBL they had on 4.3.7. In the same replayed state, they render 39-50% darker than the pre-release capture. The toon road, gates and ball use custom GLSL and do not change. The other 4.5.0 changes (direct path, cascade skip, dense instancing, AO/DoF depth, bloom fusion, look fill, OPTION_IGNORED) do not reach this game: it authors output options and custom materials, and it has no `looks.preset`, shadows, post effects, `instances.*` or `primitives.*`. The release needs one fix here: add an environment.
