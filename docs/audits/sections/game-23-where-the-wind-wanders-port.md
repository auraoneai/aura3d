## 23. The Bellkeeper's Walk (`where-the-wind-wanders-port`)

**Live:** https://aura3d.auraone.ai/apps/the-bellkeepers-walk/ · **Source:** `apps/showcase-where-the-wind-wanders-port` · **Genre:** arcade

**State:** The game loads and plays on production. The live probe ran in the Prism cloud browser on SwiftShader software GL. It recorded no console errors and no failed requests, and the render path was `hdr-msaa` with 17 draw calls. Steady-state mean luma was 168.8 at about 12 s, with 0.1% near-black pixels and 0% clipped. The probe walked the full objective (three letters, then the bell), and the bell completion and its caption fired. The desktop build is healthy. The defects are on phones and come from the live wrapper page: `apps/.../index.html` never received the mobile CSS fix that went into the examples page, and the site credit link overlaps the touch joystick.

**4.5.0 impact:** 4.5.0 changed no game code. `git diff --stat v4.3.7 v4.5.0` over the app, example and port-shared folders touches only the app's `package.json` version. The scene has no lights, no environment and no look preset, so the lighting and fill changes do not reach it. Exposure-parity measured mean luma 188.3 both before and after. One change does apply. `main.ts:302-309` passes `qualityProfile: "production"` but no `quality`, and `renderPath.ts:152-153` treats `qualityProfile` as a deprecated preset, so quality resolves to `auto` (`renderPath.ts:157`). The scene has `effects.bloom` (`world.ts:376`), so it now runs the fused `separable` bloom chain. The only pixel check of fusion is the 1/255 measurement on the PBR viewer. This game's upgrade guide says outright: "nothing was built or run" (`docs/upgrade-4.5.0/where-the-wind-wanders-port.md:3`). The change is probably fine, but it has not been measured on this game (see the tests section).
