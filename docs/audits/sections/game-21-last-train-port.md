## 21. Lamplight Line (`last-train-port`)

**Live:** https://aura3d.auraone.ai/apps/lamplight-line/ · **Source:** `apps/showcase-last-train-port` · **Genre:** racing

**State:** The game loads and plays on production with 0 console errors, 0 failed requests and 105/105 model nodes decoded. The Prism probe ran on SwiftShader (software GL, so about 0.25 fps, not a real-GPU number). Steady-state luma with `?capture=1` was 86.3 by day, with 0% black and 0% clipped pixels and 96 coarse colours, and about 30 at night. The autopilot drove a full six-town circuit to a Silver results card, and a real R press reset the service. The renderer is healthy. The problems are in game logic and input. Phones cannot drive at all, the results card misreports score and riders, and two HUD-advertised keys do nothing in the state where players press them.

**4.5.0 impact:** The game's source did not change in the release. `git diff --stat v4.3.7 v4.5.0` shows only the `apps/showcase-last-train-port/package.json` version bump. The scene authors an HDRI (`examples/last-train-port/world.ts:176`) and no look preset, so the new authored-lights-only rule and the look fill do not apply. Live `renderPath` is `hdr-msaa` / `quality: auto` / `bloomFusion: separable`. Three things from 4.5.0 do reach this game. (1) `preserveDrawingBuffer` is now off outside `?capture=1`/`?qa=1`, so the `pixels()` QA hook reads a black canvas (D-07). (2) The 4.5.0 real-depth AO fix does nothing here, because the authored AO pass is dropped for a missing normals input (D-08). (3) Fused bloom (`separable`) has never been compared with the production chain for this game. Nobody has measured a 4.3.7 vs 4.5.0 steady-state luma for it either.

**Tests and evidence gaps**

- Every browser spec loads `/examples/last-train-port/` on the example dev server (`tests/browser/last-train-play.spec.ts:16`, `last-train-ui.spec.ts:23,48`, `last-train-port.spec.ts:18`). None loads the built `/apps/lamplight-line/` route. `evidence/exposure-parity/frames/scenes.json` records that route with a 404 and mean 22.6.
- `tests/unit/last-train-port/sim.test.ts` has no test for keep-riding, R during a service, the per-service score, the `lost` unit or Gold reachability (D-02 to D-06).
- `screens/final`, `route-health.json` (2026-10-23) and `last-train-port.json` (20 MB memory) all predate 4.5.0, as does the index poster (RH-05).
- There is no 4.3.7 vs 4.5.0 steady-state luma comparison, no fused-bloom vs production-chain diff and no real-GPU capture for this game (LIGHT-02, RP-05).
- Engine-wide items that touch this game: instanced sleepers pick one shadow cascade from the node centre (SI-1). The per-instance cull allocates new arrays every frame for the 890-instance sleepers (SI-2). A typo in `?aura3d-render=` stops the mount (RP-04).
- During an 8 s W hold, the first `?capture=1` probe session dropped to `about:blank`. A second session ran for more than 20 minutes without it. The cause is unknown, possibly SwiftShader memory pressure at about 400 MB (see D-09).
- `diagnostics().fps` reads 60 while frames advanced at about 0.25 fps, and `info.render.triangles` reads 0 with 165 draws. Both counters mislead perf triage.
- The QA hook `runCircuit()` throws "stuck waiting for ready" if called while the tram is stopped mid-route, because `runLeg` drives with empty input (`main.ts:86-93`).
