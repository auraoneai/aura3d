Evidence: `evidence/roadster-hours-port/audit-fix/` (`before-*` = base build, `after-*` = this branch; `meta.jsonl` per run, frames as JPEG; `decode.mjs` rebuilds them from a run log). Steady-state numbers use the later shots of a fixed sim state, never the first frame.

## Handoffs

1. **E5**, `tools/site/games.catalog.json` (Saltwind Highway entry, `text`, line 229): replace with "Coastal highway drive with jumps, traffic and relay gates. 33 to 35 vehicles per route, one batched mesh per vehicle model, with sun shadows; a recorded 6,124-step run replays to the original's final state." Why: C9, the current text says 92 vehicles in one batched mesh and no shadows, both wrong (`buildWorld` counts 35/35/33; `world.ts` sun has `shadow: { cascades: 1, maxDistance: 90 }`).
2. **E5**, `tools/showcase-port-pages/names.json` (`roadster-hours` `pitch`): "Coastal highway drive with jumps, traffic and relay gates: 33 to 35 vehicles per route in batched meshes, with sun shadows, sky and ocean." Why: C9, same stale count; it matches the app meta description and `package.json` now.
3. **E5**, `tests/browser/game-luma-capture.spec.ts` TARGETS: add `{ name: "saltwind-sunbreak", url: "/apps/showcase-roadster-hours-port/?level=0&autostart=1&autopilot=1" }` and `{ name: "saltwind-halo", url: "/apps/showcase-roadster-hours-port/?level=2&autostart=1&autopilot=1" }`. Why: LIGHT-02 asks for every game in the harness; this lane's own spec has the per-game numbers. The harness READY probe (`dataset.aura3dReady` or `__AURA3D_LIVE_APPS__`) is untested on this game; `window.__AURA_ROADSTER_HOURS__.ready` is the game's own flag.
4. **E5**, touch-input game-check (cross-cutting): this game now has `#touch-*` buttons bound through `bindGameTouchControls`; the check can use it as a passing case.
5. **E2** (owner of the post factories), `packages/engine/src/agent-api/nodes/effects.post.ts` `postEffectBuilders.bloom` and the `AuraEffectNode` type: accept `scatter` and copy it into the node (`...(options.scatter !== undefined ? { scatter: options.scatter } : {})`). Why: C11, `mapBloomOptionsV2` reads `scatter` but the factory drops it and the type rejects it, so no game can migrate off the deprecated `radius` without its bloom changing to the default scatter 0.7. Once that lands, this game changes `radius` to `scatter` in `look.ts` and `world.ts` (same values).
6. **E3**, sun shadow on `material.custom` terrain (`a3dSunShadowAuto`): with `?shadow=1` the frame darkens far more than the casters explain (mean luma 96.3 to 77.4 on the base, 96.4 to 77.2 on the branch; `port-sun-shadows-roadster-hours.spec.ts` fails on both, limit is a 4-luma drop). Likely SI-1: the single 90 m cascade is picked per draw from the node, and the terrain flanks are single draws spanning the whole route. Frames: `evidence/roadster-hours-port/audit-fix/sun-shadow-{before,after}/`. Why: pre-existing, not a lane row; the fix belongs to the cascade selection.
7. **E1**, `packages/engine/src/agent-api/app/frameLoop.ts` authored-backing resize (`authoredBackingResize`, `renderer.resize`): with `resize: false` and a game that resizes its canvas on `window.resize` (this game, also heatsink-port and drift-and-deliver-port), growing the window after load (1280x720 to 1440x900) leaves the frame at the old size in the top-left with black bands (mean luma 13.7 in the bands against 86.8 inside, base and branch: `evidence/roadster-hours-port/audit-fix/resize-band/`, runs `g22-before-screens3` and `g22-after-screens3`). Why: a player rotating a tablet or leaving split view gets a partly black screen; shrinking is fine. The game-side fix would be to drop its own sizing and use `resize: true`, but that changes the backing ratio contract (the game caps at 1.5x device pixels while passing `pixelRatio: 1`), so it waits for the engine behaviour.
