### Checks behind the decision

1. **No game-side `lookFill` drop is needed.** E2 commit 0f99e0240 (`audit-fix/e2`) makes `createProductionRuntimeEnvironment` and both PRD-02 sources apply `dropShadowedLookFill` to the node set they resolve (`packages/engine/src/agent-api/compiler/environment.ts`, `return dropShadowedLookFill(snapshot.nodes)`). A look added through `app.nodes.add`, which is what `swapLook` does (`core.ts:641-647`), now yields its fill next to the game's `lights.ambient` 0.42 (`core.ts:314`) the same way a mounted look does in `scene().toJSON()`. Dropping the fill inside `buildLookGroup` (`core.ts:243-276`) as well would duplicate the engine rule, so the handoff is correct and I made no change.
2. **The stale mounted look is real and is engine-side.** On this branch, `CompiledSceneImpl.removeSubtree` (`packages/engine/src/agent-api/compiler/compileScene.ts:242-249`) looks up `dynamicFlat`, which only holds nodes added at runtime (`addSubtree`, line 184). For a node from the mounted scene it falls back to `liveNodes.filter((n) => runtimeIdOf(n) === runtimeId)`. Groups are gone after flattening, so the mount-time `look` group (`buildScene`, `core.ts:308`) matches nothing and `app.nodes.remove("look")` returns false. The theme 0 environment, key light and AO stay live under themes 3 and 4. Later swaps (between two runtime-added looks) do remove correctly, because those looks are in `dynamicFlat`.
3. **The E1 fix has not landed.** `git diff audit-fix/integration audit-fix/e1 -- packages/engine/src/agent-api/compiler/compileScene.ts` is empty at e1 head 3255b39ea. The only E1 change in `runtimeNodes.ts` is the RP-03 direct-path remount (0c563444e), which does not touch `removeSubtree`.

### Why there is no remote run in wave 2

Nothing on this branch changes pixels or gameplay, and the condition for the recapture (E1 `removeSubtree` on the base) is not met. E2 already measured the engine yield alone (E2 report, `cross-hop theme 3` +1.7% and `theme 4` +8.1% whole-frame mean luma, bottom third within 0.1). That measurement still includes the stale theme 0 look. The 4.3.7-vs-final capture of themes 3 and 4 is still open for CH-10. Run it once `audit-fix/e1` carries the `removeSubtree` change and both E1 and E2 are on the integration branch. Use the `crosshop` target of `tests/browser/game-luma-capture.spec.ts` with `?theme=3` and `?theme=4`.

### Fallback if E1 declines the handoff

The game can avoid the stuck mount-time group without an engine change. Leave the look out of `buildScene` and add the theme 0 look with `swapLook(0)` right after mount, so every look is a runtime add and `removeSubtree` finds it in `dynamicFlat`. I did not apply this now for two reasons. It would be a second fix for the same engine defect. And on a base without E2's LIGHT-07 change, the environment knob is computed once at mount, when the scene would have no environment, so theme 0 would lose its IBL.
