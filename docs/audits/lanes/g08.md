| `apps/showcase-aura-diamond-3d/src/main.ts` (audit line 1002; line 849 on this branch), `renderer: { quality: "high" }`: optionally switch to `{ tier: "auto" }` or keep `"high"` and accept the new `RENDERER_QUALITY_STRING` warning | E1 | Kept `"high"`, no code change. The new warning is accepted. | See below. |

Why the option was kept:

- On this base, `"high"` and `{ tier: "high" }` resolve identically. `resolveMountQuality` (`packages/engine/src/agent-api/compiler/renderer.ts:517-524`) falls back to `"high"` for the string form, and `parseQualityRendererOptions` (`packages/engine/src/agent-api/app/rendererOptions.ts:195-207`) parses both forms to the same tier. With E1's `0c563444e` the string is honoured as `"high"`, so the mount does not change.
- Switching to `"auto"` would let the tier follow the device and the adaptive governor at runtime. All wave-1 look-dev and the phone captures (`dia-shot-sandlot-phone`, `dia-shot-skyline-phone`) were judged at the fixed `"high"` tier. Whether `"auto"` is better on phones can only be shown on real phone GPUs; the remote runner is software WebGL2.
- Rewriting to `{ tier: "high" }` would only hide the warning while keeping the same fixed tier on phones, which is what the warning is there to report. Keeping the string form leaves that visible.
- No pixels or gameplay change, so no remote run was taken. `node tools/game-checks/run.mjs aura-diamond-3d`: 0 errors, 0 warnings.
