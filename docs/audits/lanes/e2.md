## Handoffs

1. **E1** (`packages/engine/src/agent-api/app/runtimeNodes.ts` and the `CompiledSceneImpl.removeSubtree` it calls in `compiler/compileScene.ts`): `app.nodes.remove(id)` on a node that was part of the mounted scene is a no-op under A3D_QR_COMPILER when that node is a group or look. `liveNodes` holds the flattened scene, groups disappear in `flattenSceneNodes`, so `liveNodes.filter((n) => runtimeIdOf(n) === runtimeId)` finds nothing and the children stay. Change: in the `CompiledSceneImpl` constructor, record the flattened descendants of each top-level runtime node (flatten each top-level node on its own and keep those objects as `liveNodes`), store them in `dynamicFlat` under the root's runtime id, and let `removeSubtree` use that map for mounted roots too. Why: Cross Hop `swapLook` (`core.ts:641-647`) removes `look` and adds the next theme's look; today the theme 0 HDRI environment, its key light and its AO stay live, so themes 3 and 4 are lit by the outdoor-day HDRI and two key lights. This also blocks the visible part of LIGHT-04.
2. **E5** (`tests/browser/example-dev-server.ts`): the `/aura-assets/` branch of `resolveRequest` lists only `public/` and the template trees, so app-level `apps/<app>/public/aura-assets/*` (Cross Hop's 25 GLBs, Bunker Zero's 8) return 404 and the route never mounts. Add `for (const appPublic of appPublicDirs(root)) candidates.push(join(appPublic, normalizedPath.replace(/^[/\\]?/, "")));` to that branch. The lane spec works around it with a `page.route` fallback.
3. **E5** (`tools/remote-acr/README.md`): document that `EXTRA_DIRS` must include `apps/common apps/showcase-port-shared` for any showcase app (every port and top-tennis import them), that ports should be captured through `examples/<dir>/index.html` (the app bundle breaks `new URL("./assets/...", import.meta.url)` model paths), and that `SPECS` must not contain `|`.
4. **E5** (`CHANGELOG.md`): entry: "Hemisphere lights now light scenes that also have an environment, and are applied per normal (sky on up-facing, ground on down-facing surfaces) instead of as one flat colour. A look added at runtime next to an authored ambient light drops its fill, as a mounted one does. The environment intensity follows environments added at runtime. `diagnostics().post` no longer reports SSAO dropped for missing normals (it never needed them) and lists the S2 GTAO stage when it runs. New warning `CONTACT_SHADOWS_WEAK_KEY`." Per-game deltas are in the table above.
5. **E5** (`tools/game-checks/**`, LIGHT-11): the "hemisphere next to an environment" check is no longer a defect check (the light now contributes); a "contact shadows on a weak key" check can match the engine warning `CONTACT_SHADOWS_WEAK_KEY`.
6. **G15, G16, G17, G19** (LIGHT-01 game side): when you add `environments.neutral({ intensity })`, your `lights.hemisphere` now keeps contributing next to it (LIGHT-05), and it is directional. Calibrate the neutral intensity with the hemisphere on; do not expect the old flat mean.
7. **G01, G11, G10, G13** (LIGHT-03): the hemisphere is now directional. Measured: top-tennis +7.7%, dot-dash-3d +6.9%, Links Neon Bay +6.6% and Mare +1.0%, bunker-zero -0.5%. Retune `lights.hemisphere` against these.
8. **G02, G03, G04, G12, G18, G20, G24, G25, G10** (LIGHT-05): the authored hemisphere now adds to your HDRI or neutral environment. Measured: drift-and-deliver-port +10.7%, teleoperator +5.1%, silt-and-signal-port +4.3%, roadster-rush +2.9%, cloud-runner-port +1.0%, slingshot-siege +0.5%, Links day courses +0.2 to +0.4%, heatsink -0.3%. ninja-runner-port not measured (timeouts). For teleoperator C14 (blown-out pod), the hemisphere is now a cause too.
