# Aura3D Product Boundaries

Date: 2026-08-08
Status: Aura3D 1.6.0 canonical product boundary

Aura3D is a developer SDK, asset pipeline, template system, diagnostics surface,
and agent-readable documentation set for browser 3D apps. It is not a hidden
provider-backed scene-generation runtime, content generator, or all-purpose game engine.

## Authoring Model

The supported agent authoring model is source code:

```ts
import { createAuraApp, lights, model, scene } from "@aura3d/engine";
import { assets } from "./aura-assets";

createAuraApp("#app", {
  scene: scene().add(model(assets.robot)).add(lights.studio())
});
```

Agents write normal TypeScript or JavaScript against public Aura3D APIs.

## What Aura3D Owns

- public `@aura3d/engine` APIs;
- `createAuraApp` lifecycle and runtime handles;
- typed GLB/glTF asset references generated by the CLI;
- starter templates and scene kits;
- diagnostics, screenshots, route-health conventions, and deployment checks;
- agent-readable rules in `llms.txt` and docs.

## What Aura3D Does Not Own

- new production art generation from scratch;
- licensing decisions for user assets;
- hidden provider-backed scene generation;
- a server-side OpenAI, Anthropic, Gemini, or local-model proxy;
- a guarantee that root `createAuraApp` defaults to every production-runtime
  renderer capability; each bridged feature still needs root-only proof;
- production game kits for every genre;
- public-quality racing or platformer generation until retained game-geometry
  evidence proves asset-bound road topology or playable surfaces;
- commercial game-engine completeness or DCC replacement.

## Asset Boundary

Use the Aura3D CLI for asset registration:

```bash
npx @aura3d/cli@latest assets add ./assets/model.glb --name model
```

Or use catalog search/resolve where appropriate:

```bash
npx @aura3d/cli@latest assets search "battle-worn knight helmet"
npx @aura3d/cli@latest assets resolve "battle-worn knight helmet" --name helmet
```

Then import typed assets and use `model(assets.helmet)`.

Do not invent asset URLs, raw GLB paths, string asset IDs, or catalog provenance.
Do not use primitives as substitutes for named real-world objects when a typed
asset is required.

## Renderer Boundary

Public examples that claim the root safe API must import only
`@aura3d/engine`. Internal rendering package evidence can be cited only as
internal or roadmap evidence unless a public root route proves the same behavior
with pixels.

## Showcase Boundary

Showcase routes are evidence artifacts. They can be:

- release-ready candidates;
- internal diagnostics;
- prototype-blocked routes;
- index routes;
- removed-from-public-showcase routes.

They are not public release candidates until they pass
`docs/project/showcase/quality-gates.md` and
`docs/project/showcase-visual-review.json`.

Turbo Drift Circuit and Skyline Runner have bounded geometry, gameplay, and
automated visual-QA evidence but remain `prototype-blocked`. They cannot be
promoted in 1.6.0 and do not establish production-game or arbitrary-GLB
conversion capability. The superseded Racing Game Layer Proof and Platformer
Game Layer Proof routes remain excluded from current public claims.

## Prompt Boundary

Aura3D may provide prompt plans, recipe docs, and agent-readable instructions.
The public product should not be described as a provider runtime, prompt-to-IR
compiler, or consumer prompt-only 3D app unless a future shipped product exposes
and documents that surface.

## Claim Boundary

Claims must use the labels and scopes in `docs/project/claim-guidelines.md`.
Deleted PRDs, roadmap items, local-only reports, and internal package tests are
not public claim proof by themselves.
