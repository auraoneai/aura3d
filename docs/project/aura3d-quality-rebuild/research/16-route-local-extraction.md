# 16 - Route-local systems -> shared-engine extraction matrix

Scope: the 18 game routes (`apps/aura-clash-showcase`, `apps/showcase-{blockfall-reactor,skyline-runner,turbo-drift-circuit,siege-golf,aurora-lander,neon-swarm,gravity-post,courier-rush,pulse-tunnel,mech-hangar,vault-breakers,rooftop-buckets,gallery-shift,deep-recovery,patrol-wing,bank-shot,orbital-defense}`) plus `apps/common`.
Method: static only (`rg` counts, file classification, reading the engine namespaces in `packages/engine/src/agent-api/index.ts`, `GameRuntime.ts`, `GameFeel.ts`, `GameCameraRigs.ts`, `game/GameAudio.ts`). No builds, no browsers. LOC = `wc -l` and excludes `src/generated/**` and `aura-assets.ts`. Counts are approximate.

## Headline findings

1. **No shared game layer exists.** `apps/common` (969 LOC) is not a game library: `runtime.ts` (885) serves the non-game viewer apps (`architecture-viewer`, `character-viewer`, ...). Games share only `rapier-physics-proof.ts` (84 LOC, evidence), imported by 2 of them (blockfall, turbo). Every other system is re-implemented per route.
2. **About a third of game code is evidence/test plumbing.** Across the 18 routes: ~29.9k LOC evidence/proof/capture/review, ~29.8k presentation, ~28.0k gameplay (plus 34.3k generated geometry). pulse-tunnel is 65% evidence, gravity-post 48%, aura-clash 47%, turbo 42%, skyline 40%.
3. **`capture=review` renders a different game.** 16 of 18 routes parse `?capture=review` locally (same `new URLSearchParams(...).get("capture") === "review"` line copy-pasted) and branch on it **395 times** (`visualReviewCapture ? a : b`). The branches change light intensities, emissive values, materials, actor scale and animation pose, not only the camera. Example `apps/showcase-rooftop-buckets/src/main.ts:322-382` (81 ternaries in that route): emissiveIntensity 3.05 vs 1.4, ambient 0.72 vs 1.32, athlete scale 1.4 vs 1.34, shooter pose "Release" vs "Ready". Review screenshots therefore don't show what players see. This is the biggest extraction issue for quality: it needs an engine-owned capture mode that may change only camera pose and clock.
4. **Engine feel helpers are wired to nothing.** `game.effects()` and `gameFeel.create()` are data-only. Pixels exist only if the route adds `controller.nodes()` to the scene (`GameFeel.ts:1-17`, "owns no renderer"). `rg '\.nodes\(\)'` across all 18 routes returns **zero** hits. neon-swarm calls `gameEffects.spawn(...)` 7 times and never calls `update` or `nodes`. It also computes `cameraDirector.update(...)` and then discards the result (`main.ts:1667-1671`, `void cameraState`), so every `cameraDirector.impact()` there is a no-op. courier-rush, skyline and turbo call spawn/update but never mount the nodes either. As a result, routes that wanted visible hit feedback hand-rolled their own spark pools; at least 9 routes do this.
5. **Typed audio is the one success, and it was still wrapped 17 times.** 17 of 18 routes use `createGameAudio`. Each one re-declares the same ~170-LOC wrapper: `XAudioCueAssetKeys`, `XAudioCueDefinition`, `xAudioAssetReference()` (an identical hash/url/license guard), `define()`, `xAudioManifest`, `XAudioProof`, `XAudioController`, and a cached `createXAudio()` that maps `GameAudio.evidence` into a proof object. That is about 3.3k LOC of near-identical boilerplate (compare `showcase-bank-shot/src/billiards-audio.ts` with `showcase-patrol-wing/src/wing-audio.ts`).
6. **Root-API-only rule blocks existing engine code.** Routes import only `@aura3d/engine` (aura-clash is the sole exception, with deep `@aura3d/*` imports in 5 files). Several mature helpers are not re-exported on that root:
   - `SeededRandom` (`packages/math/src/Random.ts`). As a result, 13 routes hand-roll `Math.imul` LCG/mulberry RNGs.
   - Terrain heightfield geometry (`packages/rendering/src/TerrainHeightfield.ts`) and Rapier heightfields (`physics-rapier/src/HeightfieldLayout.ts`). patrol-wing's README/sky.ts header explicitly cites "the root physics facade exposes no heightfield constructor".
   - `VirtualTouchJoystick` (`packages/input`): unused by any route.
7. **Engine equivalents that exist but went unused** (adoption out of 18):

   | Helper | Routes using it |
   |---|---|
   | `camera.shake` / `camera.punchIn` | 3 (aura-clash, skyline, turbo) |
   | `camera.followRig` | 1 |
   | `createTraumaShake` / `createFollowRig` (`GameCameraRigs.ts`) | 0 |
   | `game.cameraDirector` | 2 (1 of them dead) |
   | `game.hud.*` bindings | 1 (blockfall) |
   | `game.accessibility.*` | 4 |
   | `game.accessibility.pauseControls` | 0 |
   | `game.evidence` | 0 |
   | `game.touchControls` | 2 |
   | `game.inputReplay` | 2 |
   | `createGameArcadeVehicle` | 1 (courier) |
   | `effects.particles` | 2 |
   | `sky.dayNight` | 0 |
   | `lights.studio` | 1 |
   | `environments.studio` | 2 |
   | PhysicsRuntime `onTriggerEnter` | 1 (gravity-post); 5 others hand-roll "armed pair" begin/end dedup over raw `physics.world` events |
8. **Lifecycle gaps are uniform.** 0 of 18 routes handle `visibilitychange`/`document.hidden`; none auto-pause when the tab is hidden. 17 routes call `matchMedia('(prefers-reduced-motion)')` themselves. 11 routes write their own `togglePause`.

## Per-route code composition (approximate)

Classification rules:
- **Evidence:** files under `tests/`, `scripts/`, `art-review/`, `capture/`, `evidence/`, `seo/`, and file names containing proof/evidence/probe/capture/acceptance/telemetry/performance-report/poster/harness.
- **Big entry files:** `main.ts` and `*App.ts` are split into top-level statements. A statement counts as evidence when its first lines match the evidence vocabulary or more than 8% of its lines reference evidence/probe/capture/review/`__X__`.
- **Presentation vs gameplay:** presentation is audio, HUD, environment, sky, lighting, materials, feel, VFX, camera, set dressing, and art-named modules. Gameplay is everything else.

The presentation regex is broad: `table`, `arena`, `city` and `track` count as presentation, which slightly overstates presentation for pinball, billiards and courier-rush.

- **P0:** blocks honest quality or produces no pixels today.
- **P1:** large duplicated LOC with a clear API.
- **P2:** moderate duplication, or an adoption fix on an existing API.
- **P3:** nice-to-have.

## Recommended order

1. **P0, honesty first** (rows 1-3):
   - Engine-owned capture mode plus a lint rule that forbids capture-conditioned looks.
   - Effects controllers that render their own nodes.
   - A camera chase rig that the app applies.

   Without these, screenshots misrepresent play and "feel" calls are no-ops.
2. **P1, delete boilerplate** (rows 4-8): audio cue sets, look presets, light rigs, `game.evidence.publish`, `game.session`. Together these remove an estimated 6-8k route LOC and most of the 395 review ternaries.
3. **P2, adoption** (rows 9-16): mostly re-exports (RNG, heightfield, trails) and migrations onto APIs that already exist (PhysicsRuntime triggers, touch controls, input/gamepad).
4. **P3** (rows 17-21): genre kits and tooling.

## Caveats

- Composition percentages come from a heuristic classifier over top-level statements; treat them as ±10 points.
- I verified "no pixels from `game.effects`/`gameFeel`" by grep only: no `.nodes()` consumer exists in any route, and `GameFeel.ts` states it owns no renderer. A browser check would confirm it.
- LOC for inline main.ts systems are line-range estimates.
