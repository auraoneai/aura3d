# Aura3D Deployment Rollback Plan

Version: 5.6.0

Aura3D has two public deployment tracks:

- **Canonical product site:** Cloudflare Pages project `aura3d` (VeerOne account), branded as
  `https://aura3d.auraone.ai` (`CNAME` to `aura3d.pages.dev`). This serves the marketing site,
  docs, showcase library, the 30 live games and public app routes. The Veer app is the separate
  Pages project `aura3d-wonder-world` (`https://veer.auraone.ai`). The site is never deployed to
  Vercel; deploy steps are in `docs/agents/shipping-and-deploy.md`.
- **Secondary static demo:** GitHub Pages through
  `.github/workflows/public-demo-deploy.yml`. That workflow deploys the static
  external demos generated by `pnpm build:external-demos`; it is not the canonical
  branded production target.

## Record the rollback target first

Before any production deploy, record the current production deployment id for each project:

```bash
source ~/.config/auraone/cloudflare-env.sh
for p in aura3d-wonder-world aura3d; do
  wrangler pages deployment list --project-name "$p" --environment production --json \
    | node -e 'let s="";process.stdin.on("data",d=>s+=d).on("end",()=>{const a=JSON.parse(s);console.log(a[0].Id||a[0].id)})' > "rollback-$p.id"
done
```

## Rollback Rules

1. Keep the previous package artifact or hosted demo build available until the new one has passed smoke checks.
2. Verify the public URL or package install path, not just the local dev server.
3. If a deployment report, route health report, screenshot, or package smoke report fails, roll back to the last known passing artifact.
4. Update public docs only after the deployed artifact and docs point to the same version and evidence.

## Cloudflare Pages Rollback

Wrangler has no Pages rollback command; use the v4 API with the id recorded above:

```bash
source ~/.config/auraone/cloudflare-env.sh
p=aura3d
curl -fsS -X POST -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  "https://api.cloudflare.com/client/v4/accounts/$CLOUDFLARE_ACCOUNT_ID/pages/projects/$p/deployments/$(cat rollback-$p.id)/rollback"
```

Verify the rollback:

```bash
curl -fsSIL https://aura3d.auraone.ai/
curl -fsSIL https://aura3d.auraone.ai/apps/showcase-index/
curl -fsSIL https://aura3d.auraone.ai/apps/showcase-top-tennis/
```

The rollback is complete only when the branded domain serves the retained
deployment, the routes return HTTP 200, TLS remains valid, and a real-GPU check of
representative games passes. Prefer fixing forward with a new site-only deploy
(`wrangler pages deploy marketing/dist --project-name aura3d --branch main`).

## Evidence Requirements

Deployment evidence should include:

- package version;
- git revision;
- build command;
- URL or package artifact path;
- smoke-test command and result;
- known unsupported browsers/devices.

For the GitHub Pages external demo workflow, evidence should also include the generated `public-deployment-manifest.json`, `static-integrity-manifest.json`, `deployment-command-plan.json`, and a passing `pnpm verify:public-demo-deployment` result for `A3D_PUBLIC_DEMO_URL`.

The 2026-07-23 evidence bundle under `docs/project/production-evidence/2026-07-23/`
is historical (it predates the move to Cloudflare Pages). Local examples and local static
exports are not public deployment evidence by themselves.
