# `createAuraApp` production renderer path

Status: production runtime is the normal root path; renderer-feature claims
remain evidence-gated.

Owner areas: `packages/engine/src/agent-api/`,
`packages/engine/src/production-runtime/`, `packages/rendering/src/`,
`tests/browser/`.

## How to use it

Every renderable scene composed from safe public nodes uses the production
runtime by default. Primitives and generated typed GLB assets follow the same
path. Raw URLs, `unsafeModelUrl`, and unhashed inline model definitions are
rejected from production mode.

```ts
import { createAuraApp, model, scene } from "@aura3d/engine";
import { assets } from "./aura-assets";

createAuraApp("#app", {
  renderer: {
    mode: "production",
    fallback: "safe-basic",
    qualityProfile: "production"
  },
  scene: scene().add(model(assets.hero))
});
```

Omit `renderer` entirely and the default quality profile is `safe-basic`. That
profile still selects `rendererMode: "production"` — the conservative feature
set on the production backend, not the compatibility WebGL2 renderer. Explicit
`mode: "safe-basic"` is the compatibility fallback.

Types live on `AuraRendererMode` (`"safe-basic" | "production"`) and
`AuraRendererQualityProfileId`
(`"safe-basic" | "production" | "cinematic" | "experimental-webgpu"`).

## Public modes and profiles

| Public value | Kind | What it does | Claim rule |
| --- | --- | --- | --- |
| `safe-basic` | Default profile | Production backend, conservative features | Backend selection only; not production-feature proof |
| `production` | Mode / profile | Normal path for primitives and typed assets | Individual features still need their own screenshots |
| `cinematic` | Request profile | Stricter screenshot / postprocess expectations | Status is `fallback-only` until those pixels exist |
| `experimental-webgpu` | Request profile | Native WebGPU request | Requires adapter, backend, dispatch, render, and fallback evidence |

Backend selection is not feature parity. `mode: "production"` proves the
production-runtime mounted. It does not prove full PBR, HDR/IBL, shadows,
postprocess, WebGPU, skinning, or morphs.

The exact selection/lifecycle boundary is generated by
`pnpm renderer:public-path` at
`tests/reports/public-renderer-normal-path/report.json`.

## What the bridge does

1. `createAuraApp` receives an optional renderer mode and quality profile.
2. The scene builder emits an `AuraSceneSnapshot`.
3. The bridge converts that snapshot into production-runtime render sources
   without exposing renderer internals to public examples.
4. Typed asset refs stay as `AuraAssetRef` objects.
5. Diagnostics report backend, fallback, loaded typed assets, and failures.
6. Route-health publishes `renderer.mode === "production"` only when that
   backend actually initialized.
7. If production initialization fails, `safe-basic` fallback is explicit and
   the route must not claim production capability.

Typed GLB actors bind through
`packages/engine/src/production-runtime/TypedGLBActor.ts`. Public examples
must not import `@aura3d/engine/advanced-runtime`, `rendering/src`,
`GLTFLoader`, `three`, raw GLB/glTF URLs, or string asset ids.

## Evidence-gated limits

These rows stay evidence-gated even when the backend is production. Do not
infer root support from backend selection:

- full PBR / material parity, normal maps, glass/transmission, clearcoat
- HDR/IBL and production tone mapping
- shadow-map sampling and postprocess pass chains
- native WebGPU
- skinned animation and morph targets beyond the named proven routes

See [`docs/project/status/known-limits.md`](../status/known-limits.md) and
[`docs/project/status/current-state.md`](../status/current-state.md).
