# `createAuraApp` Production-Renderer Bridge Architecture

Status: production runtime is the normal root path; renderer-feature parity remains evidence-gated
Priority: P0  
Owner areas: `packages/engine/src/index.ts`, `packages/engine/src/agent-api/`,
`packages/engine/src/production-runtime/`, `rendering/src/`,
`tests/browser/`

## Decision

Use the production runtime by default for every renderable scene composed from
safe public nodes. Primitives and generated typed GLB assets follow the same
normal path. Raw URLs, remote `unsafeModelUrl` models, and unhashed inline model
definitions are rejected from production mode with migration guidance rather
than silently changing the renderer:

```ts
createAuraApp("#app", {
  renderer: {
    mode: "production",
    fallback: "safe-basic",
    qualityProfile: "production"
  },
  scene: scene().add(model(assets.hero))
});
```

Backend selection is not feature parity. `mode: "production"` and the default
`safe-basic` quality profile prove only that a safe renderable scene mounted
`production-runtime`. Full PBR, HDR, shadows, postprocess, WebGPU, skinning,
morphs, and context-resource recovery still require their own root-only browser
diagnostics and pixel evidence. The exact selection/lifecycle boundary is
generated by `pnpm renderer:public-path` in
`tests/reports/public-renderer-normal-path/report.json`.

## Public Modes and Profiles

| Public value | Kind | Purpose | Claim rule |
| --- | --- | --- | --- |
| `safe-basic` | Mode/profile | Conservative feature profile; as the default profile it selects production mode. Explicit `mode: "safe-basic"` selects the compatibility WebGL2 renderer. | Compatibility mode cannot satisfy a production-renderer claim. |
| `production` | Mode/profile | Normal public path for safe primitives and generated typed assets. | Backend is root-proven; individual features still require feature-specific proof. |
| `cinematic` | Profile | Production request plus stricter screenshot/postprocess/shadow expectations. | Fallback-only until production mode and pixel evidence exist. |
| `experimental-webgpu` | Profile | Future native WebGPU path. | Must prove adapter, backend, dispatch, render, telemetry, and fallback behavior. |

## Bridge Shape

1. `createAuraApp` receives a renderer mode and quality profile.
2. The root scene builder still emits an `AuraSceneSnapshot`.
3. The bridge converts the snapshot into production-runtime render sources
   without exposing renderer internals to public examples.
4. Typed asset refs stay as typed `AuraAssetRef` objects. Raw string ids,
   `unsafeModelUrl`, and raw GLB/glTF URLs remain invalid in public examples.
5. The production runtime returns capability evidence:
   renderer backend, fallback mode, loaded typed assets, material support,
   animation/skinning support, postprocess support, frame timing, and failures.
6. `createAuraApp` publishes route-health evidence so screenshot tests can
   reject mismatched claims.
7. Unsafe/raw model input is rejected before mount. If a real production
   initialization failure uses the safe-basic compatibility fallback, that
   fallback is explicit and the route cannot claim production capability.
8. Canvas2D remains a diagnostic schematic for non-renderable/headless
   inspection. Renderable scenes without WebGL2 fail clearly instead of drawing
   a fake frame.

## Acceptance Tests Before Claim

The normal-path boundary is proven only while browser tests show:

- a route imports only from `@aura3d/engine` plus generated `./src/aura-assets`;
- default `createAuraApp(...)` renders primitives through `production-runtime`;
- `createAuraApp({ renderer: { mode: "production" } })` renders a typed GLB;
- screenshots prove the typed GLB is visible and not a primitive substitute;
- route-health says `renderer.mode === "production"` only when the production
  backend actually initialized;
- unsafe/raw production input is rejected with typed-asset migration guidance;
- explicit or initialization fallback diagnostics do not overclaim;
- quality profiles change measurable pixels or diagnostics;
- resize and DPR survive pixel-backed production renders;
- pause/resume, context loss/restoration, and disposal are reachable through the
  public app handle and tested;
- no root-safe route imports `@aura3d/engine/advanced-runtime`, `rendering/src`,
  `GLTFLoader`, `three`, raw GLB/glTF URLs, or string asset ids.

## Open Implementation Work

This architecture decision does not complete renderer parity. The PRD remains
open for controlled root texture proof, normal maps, glass/transmission,
physical clearcoat, full material correctness, HDR/IBL, shadows, postprocess,
WebGPU, stronger context restoration, and current Three.js comparison. Those
rows must not infer support merely because the normal backend is production.
