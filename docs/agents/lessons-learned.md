# Lessons learned (4.1.x and 4.2.0 programs)

Every entry is a mistake that really shipped or nearly shipped while 26 games were built, ported and reworked. Read the section for the thing you are building; run `node tools/game-checks/run.mjs <game-slug>` before you call a game done (check ids in backticks). Detail lives in the linked evidence. All numbers are software WebGL2 unless stated; nothing here is real-GPU evidence.

Format: **ID title.** Symptom. Cause. Avoid / prevent (API or check). Evidence.

## Rendering

- **R1 Canvas hand-resized after ready.** Game fills 2/3 of the frame on Retina; resize does nothing. The port set `canvas.width/height` after `app.ready()`, so the renderer kept the old backing size. Let the engine size the canvas (`resize` option, `createParentFit`); never assign canvas size after ready. Check `canvas-resize`. `evidence/kid-goku-beyond-the-clouds-port/rework/render-fix/`.
- **R2 `ready()` is not "first frame is whole".** First visible frame drew 47 of 113 calls; HDRI finished later and recompiled everything. Programs compile asynchronously and a pending draw is skipped. `await warmPrograms(app)` (waits for programs and the environment) before showing the game. `evidence/drift-and-deliver-port/rework/render-fix/`.
- **R3 Parent grows with its canvas.** Canvas chased an auto-height `<body>` that also held the HUD and grew on every resize until GL drew nothing (black frame). `createParentFit` keeps the mounted size when a resize moves the parent; give the canvas a fixed-size container. `docs/agents/troubleshooting.md` (black-frame checklist).
- **R4 Texture upgrade is slow, not broken.** White car and trees for 25 to 50 s per material on software GL. Textures upgrade one material at a time in scene order. Add the hero first; wait for the QA hook texture status before capturing; do not file it as a material bug. `evidence/roadster-hours-port/rework/render-fix/`.
- **R5 Colour applied twice.** Platforms rendered near-black. Instance colour and material colour were both applied (squared). Apply once; check frames for dark props. `evidence/cross-hop/rework/content-fix/`. The same happens with `primitives.box({ material, instanceColors })`: the shader multiplies the material colour by each instance colour (`v_vertexColor = a_color * a_instanceColor`), so put the palette in one of them, not both, or dark palettes go black. Bunker Zero's walls on floors 2 to 6 and the Kill House drew near black on 4.3.7 and 4.5.0 for this reason (fixed in 949fe2259).
- **R6 Noisy mesh normals.** Blue-silver sheen on the golfer, blotchy robotaxi. Meshy normals are noisy; recompute smooth normals or lower specular. `tools/gridlock-car-retexture (later replaced by a regenerated closed-mesh car, tools/gridlock-courier-bake)`, `evidence/teleoperator/rework/last-fix/`.
- **R7 Model stretched on one axis.** Houses smeared up to 3x. Cap non-uniform scale (about 1.6x); regenerate if more is needed. `evidence/ninja-runner-port/rework/ui-fix/`, `docs/agents/art-direction.md`.
- **R8 Shard-atlas textures.** Skin-toned fragments and noise on carts and athletes (many Meshy atlases are shard collages). Repaint by region (flat materials, hem band) or regenerate; do not ship the atlas. `tools/hoops-athlete-retexture`.
- **R9 Failed model blanks the scene silently.** One missing GLB gave a black game. Log the failure (`RENDERER_MOUNT_FAILED`), keep a fallback, stage every GLB in captures. `docs/agents/troubleshooting.md`.
- **R10 A throwing `onFrame` stopped drawing.** Frame loop died without a message. Use `createFrameErrorBoundary` (`@aura3d/debug`); the engine now reports once and continues.
- **R11 Custom shader declared its own precision.** `precision highp float;` in a `material.custom` fragment failed to compile. The prelude declares it; do not repeat it.
- **R12 Environment 404 in published apps.** `/aura-environments/neutral.manifest.json` was missing from packages. Fixed by embedding the neutral environment (4.2.0); never depend on files that live only in the repo `public/`.
- **R13 Stock `vite build` failed.** `node:fs` reached the browser through `@aura3d/assets`. Import `@aura3d/assets/browser`; run `node tools/release/consumer-build-smoke.mjs` before release.
- **R14 Effects tuned without watching real frames.** FC 4.3.0 shipped with white and yellow particle clusters left all over the pitch and a camera that shook on every pass. Game effects were forwarded to `app.effects.spawn`, a continuous emitter nobody stopped (26 live particles after 0.2 s, 190 after 3 s from four effects), and the preset camera shake stacked on the game's own juice. Stop emitters when the effect ends (`createGameEffects` does now, with `camera: false`), cap trauma (`shake.configure({ maxTrauma })`), keep rotation under about 0.5 degrees, and probe the live particle count and trauma per frame after every event (`tests/browser/fcball-fx.spec.ts`) instead of eyeballing one still.
- **R15 Preset parameters never reached the emitter.** Gold, blue, yellow and white bubbles hung over Iron Crown and FC. `app.effects.spawn("kind")` started a continuous emitter, and `spawn` and `burst` both dropped the preset's life, size and spread, so every hit spark, dust puff and aura burst lived 1.2 to 2.4 s as a 5 to 14 cm glowing disc. Named presets are now one-shots with their own life, size and spread (`docs/api/vfx-presets.md`); the same release removed a double pixel-ratio on attenuated `points()`. Read frames at DPR 1 and 2 after touching effects, and assert the live particle count falls to zero after the preset life (`tests/qr/prd07/unit/preset-lifetime.test.ts`).
- **R16 A hypothesis about the owner's GPU needs the GPU's numbers.** The 4.3.4 point-size cap rested on 'software GL clamps point size', which was never measured; the cloud browser's SwiftShader reports `ALIASED_POINT_SIZE_RANGE` [1, 1023]. Query the renderer first (`UNMASKED_RENDERER_WEBGL`, `ALIASED_POINT_SIZE_RANGE`) before explaining why a bug only reproduces on a real GPU. Until a cause is proven, ship the safe default (runtime effects off per app with `?vfx=on` to bring them back) instead of another untested fix.
- **R17 Lights with no environment lost their image-based light in 4.5.0.** Four lights-only ports went 39 to 50% darker on their GLBs (Chroma Roll towers luma 220 to 134). Since 4.5.0 a scene with authored lights and no `environments.*` node gets no implicit room, so GLBs lose reflections and fill. Add `environments.neutral({ intensity })` and calibrate it on a steady-state capture against the previous release. Check `lighting`. Audit LIGHT-01, `docs/audits/live-games-4.5.0-audit-2026-10-29.md`.
- **R18 Hemisphere next to an environment or a look.** In 4.5.0 an environment node dropped an authored `lights.hemisphere`, and a no-HDRI look whose fill yields to an ambient added the hemisphere to the ambient term (top-tennis 0.49 to 0.86, Glint Courier +18% luma). After the audit fixes the hemisphere contributes next to an environment too, per normal (sky on up-facing, ground on down-facing surfaces), so a game that kept a dead hemisphere gets brighter: capture before tuning its intensity. Contact shadows under a weak key now raise `CONTACT_SHADOWS_WEAK_KEY` in `app.diagnostics().warnings`. Audit LIGHT-03, LIGHT-05, LIGHT-09.
- **R19 A look added at runtime kept its fill.** Cross Hop's theme swap adds a look through `app.nodes` next to an authored ambient; in 4.5.0 the fill only yielded when the scene was compiled, so later themes were lit twice. The fill now yields at runtime as well. Capture every theme, not only the first. Audit LIGHT-04.
- **R20 Judge the later shots.** The first frame on software GL is lit by the analytic floor probe; the baked probe lands seconds later (Aura Diamond Skyline read right on frame one and 2.6 at steady state). `tests/browser/game-luma-capture.spec.ts` logs shots at 3, 25 and 60 s for every game and lighting variant; compare the 25 s and 60 s shots.
- **R21 Mean luma hides a broken look.** Frames sat inside the mean-luma band while the sky clipped and the ground went black, and two variants with the same mean were called alike (Bunker Zero floor 1 mean 74.95; a racer at 42.6 whose sky region read 36.1). A mean averages a half-black, half-white frame to the same grey as a flat one. Judge distributions and regions, not one number: p5/p95, `darkFrac`/`clipFrac`, the 3x3 cells, named crops, mean RGB and hue (GL_META v2 in `tests/browser/game-luma-capture.spec.ts`), declared per variant in `evidence/game-upgrades-47/<slug>/luma-bands.json` and checked with `node tools/look-metrics/region-luma.mjs bands` and the `luma-band` game-check. `docs/prds/game-upgrades-47/GameUpgrades47-PRD.md` (section 1.5).
- **R22 Only one light casts a production shadow.** Lamps, spots and torches marked `shadow: true` cast nothing; only the sun's shadow map existed. Up to 4.6.x `resolveProductionShadowCasterIndex` (`packages/engine/src/agent-api/compiler/observations.ts`) picks a single caster for the whole scene, silently. Give the scene one deliberate key caster and ground local lights with contact or blob shadows; from 4.7.0 (lane E-B) up to `localShadowLights` local casters per quality tier (0/1/2/4) cast as well; read `app.diagnostics().lighting.localShadowLights` on a capture before you claim a second shadow.

## Motion and physics

- **M1 Fixed-step sim drawn without interpolation.** Entity still on 50% of frames at 120 Hz (58% at 144 Hz), clips flip about 1,200 times per 10 s, reads as shake. Draw between the last two steps: `createFixedStepPresenter` / `createRenderInterpolator` / `loop.alpha`; prove with `runMotionGate` at 60, 120, 144 Hz. Check `fixed-step-presenter`. `docs/audit/motion-audit.md`, `docs/api/motion-presenter.md`.
- **M2 Hit-stop or timers on frozen game time.** Match froze for good after the first basket (183 of 186 frames identical). A countdown ticking on game time never ends while game time is frozen. Use `createHitStop` (real frame delta). Check `hitstop-time`. `evidence/aura-hoops-3d/rework/`.
- **M3 Pose bones as arrays.** Arms never moved, bat floated on the ground. The engine wants `{x,y,z,w}` / `{x,y,z}` objects; arrays are silently ignored. Convert at the call site; verify the pose actually applied from a frame. Check `pose-array`. `evidence/aura-diamond-3d/rework/`.
- **M4 Held items not attached.** Bat, club, racket beside the athlete. Use `attachToBone` (case- and rig-insensitive names, throws `ATTACH_BONE_NOT_FOUND`); check knob-to-palm distance over the whole swing. `docs/api/motion-attach.md`. Two-handed objects (bat, club, racket): `createTwoHandGrip` (M17).
- **M5 Sliding feet.** Walkers slid, legs "scurried". Clip speed was fixed, not driven by ground speed. `createLocomotion` (stride-synced), `createFootSlideMeter` (fails sliding and legs that never step). `docs/api/motion-locomotion.md`, `motion-foot-slide.md`. When the sim speed is far above any clip's planted-foot speed (Cumulus Dash: 14.5 m/s against 3.3), speeding the clip up and widening its swing cannot plant the feet: drive the legs by IK from ground speed (`examples/kid-goku-beyond-the-clouds-port/gait.ts`) and measure the real bones, not an analytic ratio.
- **M6 No consequence on contact.** Ran through gates, bridges, buildings, cars. Use the impact kit (`createImpactWorld`, hit-stop, shake, cue, particles, penalty); one event per contact; no pass-through at 4x speed. `docs/api/motion-impact.md`.
- **M7 Double-framed skeleton.** Players looked ghosted while kicking: procedural kit boxes drove a swing beside barely-moving legs. `checkDoubleFrame` must be clean; one skinned body per athlete.
- **M8 Counter incremented per frame.** Golf strokes climbed to 19 per swing because "committed" stayed true for the whole downswing. Count transitions, not states; unit-test with a long stepped swing.
- **M9 Camera inside scenery.** Duneglide eye was inside geometry on 153 of 300 steps. `createCameraClearance`; test in QA stepping.
- **M10 Integrator too coarse.** Exact-aim shots landed 10 cm low. Substep ballistics (1/240 s).
- **M11 Unstable hit decisions.** Hole could hang if contact was missed. Keep a timed fallback behind swept contact (60 ms) so a miss never blocks the game.
- **M12 Skinning stretch.** FC players stretched up to 120x. Smooth skin weights over the whole mesh and measure every primitive, not only the first.
- **M13 Idle hands aimed below the shoulder.** Bowed arms. Check idle pose against arm length in frames.
- **M14 Ball driven by the IK target, not the rendered hand.** Hoops dribble looked fake: the ball bounced about 0.9 m below a hand that never came down (arm reach is 0.55 m, so the rendered palm stayed above 1.0 m while the target went to 0.75 m). Drive contact objects from the bone as rendered (`socket("RightForearm")` plus the palm offset), keep the crouch until the floor contact, and bring the target heights inside the arm's reach. Measure ball-to-rendered-hand distance at the meet (<= 0.12 m) and at the floor, with a fixed sim step (`?diag=1&qaDt=0.0167`) so software-GL frame rates do not exaggerate the one-frame lag. `tests/unit/aura-hoops/dribble.test.ts`, `tests/browser/hoops-dribble-probe.spec.ts`. Now a library kit: `createHandBounce` and `measureHandBall` ([motion-hand-bounce](../api/motion-hand-bounce.md)); use it instead of hand-rolling a dribble. Second pass: the ball also ended up beside the hand (about 0.4 m) when the athlete was not in a dribble pose and when a runner's stride lead stacked on a forward palm target; fix: ride the rendered palm in every pose, no lead for a stationary handler, lead along travel only and capped, and hold the XZ offset to 0.25 m (`measureHandBall` criteria in `docs/api/motion-hand-bounce.md`).
- **M15 Fitted models are grounded on their lowest point.** Hoops put every athlete at `y + 0.96` ("origin at the centre") and the ball at its centre height, but `scaleMode: "fit"` puts a model's lowest point on the node position: the athletes hovered 0.96 m off the floor (away from ring, shadow and ball) and the ball bounced a metre below the drawn hand in every pose, while every bone-based probe passed (sockets are in the model's native space, which has its own +0.96 m origin). Place a fitted model at floor height; place a fitted ball at `centre - R*(0, radius, 0)` (it spins about its lowest point); and measure in SCREEN space (project the drawn palm and ball through the live camera: `tests/browser/hoops-dribble-screen.spec.ts`), never only in bone space. Check a side-on frame next to the floor line for any new fitted model. Check `fit-grounding` (static) flags a fitted model placed at half its height; `tests/browser/fit-grounding-sweep.spec.ts` prints every runtime node's drawn lowest point per game.
- **M15 Model forward axis assumed.** Every Bunker Zero enemy was drawn with its back to the player: the sim yaw treats -Z as forward, the Meshy GLBs look down +Z, so each actor was exactly 180 degrees off. Model forward axes are not standardised. Declare one per model (measure it: toes, muzzle), turn actors with `faceTowards`, and check a real frame of every actor kind facing the player (`facingError` at most 10 degrees, converged within 0.4 s).
- **M16 Passes launched as lobs.** FC passes left the boot at 20 to 28 degrees (median apex 1.28 m), so every pass hopped and bounced like a basketball. A ground pass leaves at 2 to 4 degrees with the speed the receiver's distance needs (`launchKick` weights it from the lead point, arrival about 5 m/s), air drag is quadratic (a = 0.010 v^2), a rebound under 1.4 m/s settles into a roll, and the orientation rolls v/r about the axis perpendicular to travel. `tests/unit/aura-fc-3d/ball-physics.test.ts` measures trajectories (20 m/s ground pass rolls about 44 m, bounce heights 0.5 to 0.6 of the last, curl direction).
- **M17 Grip measured on the bone, not the drawn hand.** Diamond batter's bat floated over his head in stance with both hands at his sides: the bat followed one forearm bone, the athletes stood 0.94 m too high, the left arm reused the right arm's bind directions, the bat angles used XYZ order on a ZYX node (tilted the wrong way), and the Meshy mesh was bound mid-stride so the drawn hand sat 10 to 20 cm from the bone (about 5 cm nearer the elbow than the bind centroid). Solve both arms to grip points on the object's axis (`createTwoHandGrip`), calibrate the palm from the CPU-skinned hand vertices (`handCentroid`), set rotation in the node's own order (`gripQToEulerZYX`), and prove it with `measureGrip` over every phase (<= 0.06 m, 0.08 m tail). `docs/api/motion-two-hand-grip.md`, `evidence/aura-diamond-3d/bat-fix/`.

## Game design

- **G1 Nothing to do.** HEATSINK: free flight, no targets, no score. Every game needs a stated objective on screen from second one, a score or progress, and a result. `docs/agents/game-example-standards.md`.
- **G2 Cloned mechanics and identity.** Dot Dash looked like the arcade original (maze, pellets, four ghosts). Mechanics may be reproduced; names, characters, art, lore and layouts may not: new hero, enemies, pickups, maze language, text. `docs/workflows/crayon-game-reverse-engineering.md` section 4.
- **G3 Rules text that the game does not implement.** "32-player World Tour" while tournament was "Coming soon"; "twin cannons" not in code. Only describe what the code does; label deferred modes.
- **G4 Weapon label and model out of sync.** Bunker Zero showed a pistol label with the rifle model. One table decides the model in hand.
- **G5 Dismissable overlays that never dismiss.** Title cards stayed over the court; modals covered the scoreboard. Dismiss on start; test the first frame after start.
- **G6 Autopilot defaults.** Demo mode ran by default. Manual control is the default; autopilot is opt-in.
- **G7 A game with no real playable loop is removed, not kept.** Red Zone 3D shipped as a "playable game" card without a loop a player could finish; the owner deleted it (4.3.0). Before listing a game, play one full round (`node tools/game-checks/run.mjs <slug>` plus the objective and win/lose probes); if there is no end state, do not list it.
- **G8 Renderer node pools smaller than the simulation.** Apex Overdrive's sim held 31 vehicles, 13 heavy trucks, 6 sky cars and 38 bolts at 50 s; the renderer drew 14, 3, 5 and 19, so traffic popped in and out and bolts could hit from nothing. Slingshot Siege had 72 nodes for 83 pieces. Size each pool from the simulation's measured peak with a seeded replay test that runs the renderer's slot assignment every step (`tests/unit/roadster-rush-native/render-pools.test.ts`), and fill slots nearest-ahead first so a full pool drops the far entities, not the near ones. Audit roadster-rush RR-1, RR-2.

## Assets and likeness

- **A1 Photographic faces and real marks in textures.** Athletes carried face scans, "CRETIS 13", swoosh-style marks and crests; a cabinet texture held framed photographs of people. Repaint by region, flat faces; scan every served GLB. Check `likeness`, tests in `tests/unit/likeness-audit/`. `docs/audit/likeness-brand-audit.md`.
- **A2 Real vehicle silhouettes and lettering.** Robotaxi, Corvette, Cybercab shapes with "WAYMO"/"JAGUAR". Painting lettering out leaves smears and a recognisable shape: replace with original generic models. `evidence/teleoperator/rework/vehicles/`.
- **A3 Meshy invented emblems.** Winged badges and door marks on new cars. Render all four sides of every generated model; cover or regenerate; never name brands in prompts.
- **A4 Trademark-derived names and lore.** "Mount Paozu", "star orbs", yellow creature cheeks, fighters in a famous gi. Search code, state and text for borrowed terms; restyle palette and silhouette. Check `likeness`.
- **A5 Meshy credit tracking.** The ledger undercounted by 325 credits (4,530 vs Prism 4,855) because the old helper settled a 429 on a poll as failed although the task was charged, and it lived in `/tmp`. Meshy spend is uncapped by owner decision on 2026-10-25; credits are tracked for visibility. Reserve every paid call through `aura3d meshy ledger` (poll-429 stays `unconfirmed`), compare with `aura3d meshy ledger reconcile`, and read `meshy-cap` as information. Details: `docs/audit/meshy-reconciliation.md`.
- **A6 Raw model URLs and missing provenance.** Production needs same-origin URL + sha256 + provenance; raw GLB URLs fail `public-example-boundary`. Check `asset-provenance`; `aura3d assets validate`.
- **A7 Oversized assets.** Cross Hop shipped 70 MB of vehicle textures (3 x 2048 each). Budget per role (docs/agents/asset-workflow.md); downscale to 1024 where seen small.
- **A8 "800K+ catalog".** A hosted index row count (855,001 records, 93% Objaverse, 88% CC-BY) was marketed as a feature while its Worker was missing (404) and 3 of 20 searches found a relevant first hit. The index was retired on 2026-10-25: code, worker, refresh tools and workflow removed, and the D1 database `aura3d-asset-index` (3.3 GB) and R2 bucket `aura3d-asset-index` deleted. Agents now run `aura3d assets resolve`, which decides per need: project asset, open licence-clear source, Meshy (opt-in, budgeted) or a primitives recipe. Do not advertise unreachable services; state what a clean install can do. `docs/audit/asset-catalog-claim.md`, `docs/agents/asset-workflow.md`.
- **A9 Unlicensed or unshippable licences.** 8.8% of the index is non-commercial; CC-BY needs attribution; CC-BY-SA is not "redistributable". Record licence and attribution at admission.
- **A10 Rigs modelled in a pose.** The Aura FC athletes shipped with the shorts torn into shards behind a swinging leg; Hoops, Diamond, Links, Bunker Zero and Slingshot Siege carried the same defect (stretched triangles up to 385x; Bunker Zero and Slingshot Siege are fixed). Cause: the Meshy mesh is modelled mid-stride (knee bent, thigh swung forward, thigh made of a few huge triangles) but bound to a straight skeleton, so every clip rotates the legs about joints 10 to 20 cm off the limbs; cutting triangles only traded one defect for another. Check every rigged GLB with `aura3d assets validate --skin` before a game uses it (it runs in `validate --release`, `check-deploy --release` and `tools/game-checks`); repair with `assets repair-skin --rebuild-limbs` (separate skin, shorts and sock materials), `--refit-skeleton --keep-clips <played clips> --smooth-bridges` (one textured mesh: the joints move onto the limbs and the clips are re-targeted), or regenerate in A/T pose. Ship only the clips the game plays: the check measures every shipped clip. A four-legged mesh on a humanoid skeleton is not repairable by either: re-rig it (`tools/skin-fixes/bounding-quadruped.ts`) or generate a quadruped rig. Evidence `evidence/aura-fc-3d/legs-fix/`, `evidence/bunker-zero/rig-fix/`, `evidence/slingshot-siege/rig-fix/`, `tools/aura-fc/`, `docs/audit/game-leftovers.md` F11 and F12.

## Build and deploy

- **B1 Unanchored ignore patterns.** `.vercelignore` `evidence/` also excluded `packages/game/src/evidence/` and broke the build. Anchor with a leading slash. Check `vercelignore`.
- **B2 `.gitignore` swallowing new things.** `*.jpg`/`*.png` hid screenshots; `site/` hid `tools/site`. After adding a directory or image, `git status` must show it. Check `screens-tracked`.
- **B3 File-count limit.** Vercel stops at 15,000 files; the repo passed it. Deploy from a clean worktree with `/evidence/` ignored; report the tracked count.
- **B4 Tests the build needs.** Ignoring `tests/` broke the build (`vite.config.ts` imports `tests/browser/installed-package-resolve`). Check what the build reads before ignoring.
- **B5 Registry lag.** npm showed 2 of 24 packages for minutes after a successful publish. Poll from `/tmp`; do not re-publish.
- **B6 Release steps `prepare-version` misses.** Marketing HTML, showcase index, `CONTRIBUTING.md`, doc stamps, app `package.json` versions, the CHANGELOG version line. Run `marketing/scripts/check-version.mjs`.
- **B7 Skill mirrors stale.** `check:skills` fails when `llms.txt` changes. Sync with `tools/agent-skills/sync.ts` (via `tsx`, never pnpm in symlinked worktrees).
- **B8 Top-level await in shipped code.** The Rapier solver initialised with a top-level `await`, so a consumer bundling `@aura3d/engine` with esbuild or Vite at an `es2020` target, or to `iife`/`cjs`, failed ("Top-level await is not available"), and esbuild placed `await` inside non-async wrappers where it was reachable from an import cycle ("Unexpected reserved word", dot-dash-3d test harness). The default build keeps top-level await so `app.physics` stays synchronous; the `aura3d-no-tla` bundler condition selects a lazy build where you `await ensurePhysics()` first. New top-level `await` in shipped packages is a release gate failure (`pnpm verify:no-tla`).
- **B9 Model files that exist on disk but not in the deploy.** Teleoperator's four building GLBs were in `public/aura-assets` and referenced from `main.ts`, but not in `aura.assets.json`; the production build copies only manifest-admitted assets, so they 404ed live, `auraApp.ready()` rejected and the 3D canvas stayed black (HUD fine) in 4.3.0 and 4.3.1. Admit every model with `aura3d assets add` (or copy it route-local), run `node tools/game-checks/run.mjs --all` (`deployable-assets` fails on it), never leave `await auraApp.ready()` without a catch, give optional set dressing a fallback, and run the live smoke (`tests/browser/live-index-games.spec.ts`, `live-teleoperator-black.spec.ts`) after EVERY deploy, not only the release deploy.
- **B10 The repository-wide asset catalogue in a game bundle.** Eight games imported `src/aura-assets.ts` and shipped a 2.6 MB catalogue chunk, 522 of whose URLs are not deployed. Run `aura3d assets typegen --route apps/<app>` and import `./aura-assets.route`. Check `shared-catalog`. Audit RH-06.
