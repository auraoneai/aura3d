# Shader graph contact shadows: current source contract

This note describes the WP-05 development source, rather than a released-version guarantee. Lit graph shader variants can select a scoped contact mask for the exact directional light that produced it. The mask is tied to the producing device, frame, view, camera, time, viewport and live texture. The forward shader uses the selected light's packed or clustered index; other lights do not sample that mask. The current production prepass rejects every portable shader material, including graph materials, before publishing a mask. A graph participant identity and source-integrity proof is still needed to enable that route.

The producer uses a half-resolution camera-depth prepass and the nearest depth surface. This is a screen-space approximation, not a per-fragment depth match. It validates the whole set of participating depth items before publishing a mask: an unsafe occluder can affect another object's result. Current restrictions also include skinned or morphed participants. An active graph receiver with an authored position output is rejected. Nonopaque, depth-disabled or depth-nonwriting receivers and other incompatible coverage or depth states are also rejected. Other renderer and producer eligibility checks can further restrict a route.

`PortableShaderMaterial.hotReload()` continues to accept validated raw paired sources. For a graph material, a successful raw reload invalidates its contact-depth certificate: raw source text does not reconstruct the graph's position-output metadata, paired depth shader or lazy variants. A graph whose sources have been reloaded is rejected as a contact receiver; the production prepass currently rejects all portable materials regardless of reload. Construct a new material from the graph document to restore the source-pristine flag, which by itself does not bypass that prepass restriction. A rejected reload does not invalidate the existing flag; ordinary non-graph portable material reloads are unaffected. This contact restriction does not certify the other graph variants after a raw reload.

The focused source and mock coverage is in [`native-graph-portable-material.test.ts`](../../tests/unit/rendering/native-graph-portable-material.test.ts). It checks shader variants and linked GLSL reflection, exact-light and frame selection, checked native-shaped WebGPU submission, failure propagation, and skin/instance variant composition using a synthetic scoped publication. It also checks the clustered-light edge-tile contract. These tests do not demonstrate rendered pixels or end-to-end producer support for skinned contact scenes. WGSL compiler, browser and native GPU validation remain separate verification work.

## Graph geometry and clipping

The current graph stages apply skinning and authored position output before the geometry matrix, then apply the instance and model transforms. Local clipping uses the geometry-transformed position before instance placement; world clipping uses the final world position. The forward and custom-depth stages carry the same clipping groups. Geometry normals use an inverse-transpose transform before the model normal matrix when the geometry matrix is sufficiently nonsingular; otherwise the shader retains the input normal.

Clipped graph draws require an unchanged adapter-issued material and a matching registered shader variant. A copied or source-edited material spec, a successful raw shader reload, a modified registered variant, or a graph with user-provided GLSL `defines` does not receive this clipping certificate. Such materials can still be used for otherwise supported unclipped draws. Construct the material directly from an unmodified graph adapter spec without custom defines to use the certified path.

The focused graph tests check source, matrix order, clipping packets and native-shaped mock submissions, including expanded skinning and instances. These checks have not validated rendered pixels on WebGL2 or WebGPU, and they do not establish completion of the broader graph roadmap.
