# Aura3D 2.0 platform architecture

Status: current for Aura3D 2.0.0

Aura3D owns the browser-rendering and agent-authoring layers that create a
durable advantage. Mature commodity solvers remain external and optional. The
public API, typed asset system, scaffolds, evidence, and application workflows
form the integration layer between them.

## Aura3D-owned core

- WebGL2 and WebGPU rendering, scene graph, geometry, materials, shaders,
  lighting, shadows, textures, animation rendering, post-processing, resource
  lifecycle, and renderer diagnostics.
- Typed scene authoring and the safe `createAuraApp` API.
- Typed assets, provenance, hashes, bounds, role admission, semantic metadata,
  and deterministic CLI generation.
- Reproducible scaffolds, application workflows, evidence capture, interaction
  audits, and claim lineage.
- A bounded Three.js migration surface in `@aura3d/three-compat`.

## External or browser-standard owners

| Capability | 2.0 owner | Aura3D responsibility |
| --- | --- | --- |
| physical rigid bodies | Rapier through `@aura3d/physics-rapier` | stable descriptors, lifecycle, evidence, and optional loading |
| navigation and crowd queries | Recast/Detour through `@aura3d/navigation-recast` | adapter contract, typed inputs, lifecycle, and isolation |
| browser audio | Web Audio through `@aura3d/audio` | cues, spatial semantics, deterministic state, and unlock handling |
| compressed asset codecs | established glTF/Draco/Meshopt/KTX tooling | typed ingestion, validation, provenance, and browser-safe loading |
| React integration | React through `@aura3d/react` | thin lifecycle binding without a second renderer |

Compatibility-only ECS, scripting, broad physics, and Three-compatible packages
remain isolated from the recommended lean closure. Editor and Node-media
features are optional packages or subpaths. None enter the lean product or game
bundle unless the consumer selects them.

## Recommended package paths

- `@aura3d/lean`: recommended small browser entry for new product and arcade
  applications.
- `@aura3d/engine`: broad compatibility host and safe root authoring API.
- `@aura3d/rendering`: lower-level rendering package for advanced consumers.
- `@aura3d/physics-rapier` and `@aura3d/navigation-recast`: optional external
  solver adapters.
- `@aura3d/engine/media-node`: Node-only encoding and publishing utilities,
  excluded from browser entries.

The generated ownership inventory in
[`final-subsystem-ownership.md`](./final-subsystem-ownership.md) is the exact
package/file ledger. The migration consequences are in
[`MIGRATION-2.0.md`](../../MIGRATION-2.0.md). Public capability claims remain

## Boundary rule

Aura3D owns a component only when ownership strengthens browser rendering,
agent-oriented authoring, typed/provenance-backed assets, deterministic
application workflows, or trustworthy evidence. A mature commodity solver is
integrated behind one adapter; a duplicate or evidence-only imitation is
removed.
