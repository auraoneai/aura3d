# ADR 0012: External generated-asset import adapters remain owned by the CLI asset pipeline

- **Date:** 2026-09-04
- **Status:** accepted for Aura3D 2.0.0
- **Workstream:** 2.0 asset-quality import (no-key Meshy evidence flow)

## Context

Aura3D 2.0 adds a CLI import adapter for externally generated assets (Meshy
AI task outputs: GLB payload, metadata/rights evidence, thumbnails). This
adapter could accidentally become a parallel asset system if its ownership is
not bounded: it validates, admits, and retains third-party bytes that the
typed asset map and route gates later consume.

## Decision

`packages/aura3d-cli/src/meshy/*` is a CLI-side admission adapter whose
execution remains owned by the `@aura3d/cli` asset pipeline. It composes the
existing asset-role admission owner (`asset-role-admission.js`) and the
existing typed-asset generation flow: it may validate, quarantine, and retain
evidence for externally generated bytes, but it may not introduce a parallel
asset index, a parallel manifest format, a new package, or a new runtime
subsystem. All retained assets still flow through `aura.assets.json` and
`src/aura-assets.ts` generation, and all route consumption still passes the
existing typed-primary-asset gates.

## Evidence

CLI admission, provenance, and route-gate tests prove imported Meshy assets
reach the retained CLI pipeline implementation; R11 continues to fail any
future unreviewed source-file addition.
