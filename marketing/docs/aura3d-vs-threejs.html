Aura3D vs. three.js,
measured, with the caveats.

Aura3D is a shorter, safer path from an idea to a shipped browser scene or game, especially when an AI agent writes the code, and it ships batteries three.js does not. three.js is the smaller, faster, more mature runtime with a far larger ecosystem. This page says where each wins, with the number, the version and the caveat next to every claim.

The short version

Pick by what you are optimising.

Aura3D wraps a three.js-compatible renderer lineage, so where they share a code path the result is a tie. The differences are above the renderer: the API, the game kit, the safety rails, the agent docs and the deploy checks.

Aura3D is better at

Authoring size. Shorter scene source in four of five bench scenes (26% to 51%), one import instead of up to eight.

Game batteries. HUD, touch controls, juice, session, audio cue bank, QA hooks, fixed-step loop and replay, a safety net with black-frame self-heal, scatter and merge, a motion kit and render interpolation for 120 and 144 Hz displays.

Safety. Assets need a sha256 and provenance in production; shader failures and throwing frames are reported; check-deploy gates a route.

Agent workflow. llms.txt, 14 skills, compiled recipes, assets resolve (project asset, CC0 source, Meshy or primitives), a Meshy pipeline with credit caps.

three.js is better at

Size and speed. A one-cube bundle is 7.7x smaller (8.7x gzip) with 2 requests instead of 26; first frame 95 ms vs 3,269 ms; every frame-time row on software GL.

Authoring speed for an agent. Median 4 turns against 10, and 15 of 15 renders against 14 of 15, in the cold-start trial.

Breadth. Eight non-PBR materials, GTAO/SSR/SSGI, a WebGPU renderer, WebXR, many loaders, about 638 TSL names against 62.

Maturity. 15.2M weekly downloads, 314 versions, years of field use, R3F, drei and a hiring pool.

Ties

PBR materials, lights, primitives, instancing, helper objects, and the cube, array and stereo cameras.

The shader-water picture was identical in both libraries (JSD 0.0000), and the game-loop replay hashes were identical.

First-try builds in the cold-start trial: 15 of 15 for both.

Code comparison

The same PBR viewer, twice: 49 lines against 24.

These are the real bench sources (tools/bench-vs-threejs/pbr-viewer): a lit GLB with an HDR environment, one directional shadow, bloom and orbit controls. The three.js version needs six addon imports. The Aura3D version needs a generated assets file for the sha256 and, in 4.1.2, a Vite config (the stock build works from 4.1.3); it also carries an as never cast on the HDR texture, which is a rough edge we have not removed. One author wrote both, and that author knows three.js far better.

three.js 0.185.1 49 non-blank lines 
import * as THREE from "three";
import { GLTFLoader } from "three/examples/jsm/loaders/GLTFLoader.js";
import { RGBELoader } from "three/examples/jsm/loaders/RGBELoader.js";
import { OrbitControls } from "three/examples/jsm/controls/OrbitControls.js";
import { EffectComposer } from "three/examples/jsm/postprocessing/EffectComposer.js";
import { RenderPass } from "three/examples/jsm/postprocessing/RenderPass.js";
import { UnrealBloomPass } from "three/examples/jsm/postprocessing/UnrealBloomPass.js";
import { OutputPass } from "three/examples/jsm/postprocessing/OutputPass.js";
import type { SceneHandle } from "../../shared/glue";

export async function start(canvas: HTMLCanvasElement): Promise<SceneHandle> {
  const renderer = new THREE.WebGLRenderer({ canvas });
  renderer.setPixelRatio(1);
  renderer.setSize(640, 360, false);
  renderer.shadowMap.enabled = true;
  renderer.shadowMap.type = THREE.PCFShadowMap;
  renderer.toneMapping = THREE.ACESFilmicToneMapping;

  const scene = new THREE.Scene();
  scene.background = new THREE.Color("#1a1d24");
  const camera = new THREE.PerspectiveCamera(40, 640 / 360, 0.1, 100);
  camera.position.set(4.5, 2.2, 5.5);

  const hdr = await new RGBELoader().loadAsync("env.hdr");
  scene.environment = new THREE.PMREMGenerator(renderer).fromEquirectangular(hdr).texture;
  hdr.dispose();
  scene.environmentIntensity = 0.7;

  const sun = new THREE.DirectionalLight("#fff4e0", 1.1);
  sun.position.set(5, 8, 4);
  sun.castShadow = true;
  sun.shadow.mapSize.set(1024, 1024);
  Object.assign(sun.shadow.camera, { left: -6, right: 6, top: 6, bottom: -6, near: 1, far: 30 });
  scene.add(sun);

  const ground = new THREE.Mesh(new THREE.PlaneGeometry(30, 30), new THREE.MeshStandardMaterial({ color: "#2b2f38", roughness: 0.9 }));
  ground.rotation.x = -Math.PI / 2;
  ground.receiveShadow = true;
  scene.add(ground);

  const truck = (await new GLTFLoader().loadAsync("model.glb")).scene;
  const box = new THREE.Box3().setFromObject(truck);
  truck.scale.setScalar(2 / (box.max.y - box.min.y));
  truck.position.y = -box.min.y * truck.scale.y;
  truck.traverse((o) => { if ((o as THREE.Mesh).isMesh) { o.castShadow = true; o.receiveShadow = true; } });
  scene.add(truck);

  const controls = new OrbitControls(camera, canvas);
  controls.target.set(0, 0.8, 0);

  const composer = new EffectComposer(renderer);
  composer.setSize(640, 360);
  composer.addPass(new RenderPass(scene, camera));
  composer.addPass(new UnrealBloomPass(new THREE.Vector2(640, 360), 0.35, 0.6, 1));
  composer.addPass(new OutputPass());

  return { frame(dt) { controls.update(dt); composer.render(dt); } };
}
Aura3D 24 non-blank lines 
import { camera, createAuraApp, defineModelAssets, effects, environments, interactions, lights, material, model, primitives, scene } from "@aura3d/engine";
import type { SceneHandle } from "../../shared/glue";
import { SHA256 } from "./assets.generated";

export async function start(canvas: HTMLCanvasElement): Promise<SceneHandle> {
  const assets = defineModelAssets({ truck: { url: "/model.glb", sha256: SHA256.truck } }, { license: "CC-BY 4.0, Cesium" });
  const app = createAuraApp(canvas, {
    autoStart: false,
    resize: false,
    pixelRatio: 1,
    renderer: { mode: "production", qualityProfile: "production", fallback: "safe-basic" },
    output: { toneMapping: "aces" },
    scene: scene()
      .background("#1a1d24")
      .camera(camera.orbit({ fov: 40, near: 0.1, far: 100, position: [4.5, 2.2, 5.5], target: [0, 0.8, 0] }))
      .add(environments.hdri({ name: "env", intensity: 1, background: false, texture: { type: "texture", format: "hdr", url: "/env.hdr" } as never }))
      .add(lights.directional({ color: "#fff4e0", intensity: 2.5, position: [5, 8, 4], shadow: true }))
      .add(primitives.plane({ name: "ground", size: [30, 1, 30], material: material.pbr({ color: "#2b2f38", roughness: 0.9 }) }))
      .add(model(assets.refs.truck, { name: "truck", targetHeight: 2, castShadow: true }))
      .add(effects.bloom({ intensity: 0.35, threshold: 0.85, radius: 0.6 }))
      .add(interactions.orbit({ target: "truck" }))
  });
  await app.ready();
  return { frame(dt) { app.step(dt); } };
}
When to choose which

Choose by constraint, not by loyalty.

Choose three.js when

Runtime size, breadth or ecosystem decide it.

  • You need WebGPU, WebXR, exotic loaders, SSR, SSGI or GTAO, or the largest ecosystem (React Three Fiber, drei, tutorials, hiring pool).
  • Bundle size and first-frame time on low-end devices are the main constraint.
  • You have a large existing three.js codebase and no reason to rewrite it.
  • A person who already knows three.js is writing a quick one-off scene.
Choose Aura3D when

Shipping and maintaining a game or agent-written scene decide it.

  • An AI agent writes or maintains the scene and you want types, docs, recipes and guardrails that make wrong code fail loudly.
  • You are shipping a browser game and want HUD, touch, audio, replay, a safety net, interpolation for high-refresh displays and deploy checks without assembling them.
  • You want asset provenance and a verified deploy path.
  • You can accept a larger bundle today (the stock build is 7x to 8x larger than three.js) and WebGL2 by default.
What this does not prove

Limits we are not hiding.

No GPU claim

Every timing and render check is software WebGL2 on a CPU runner. Three games were checked on one Apple M4 Max. Nothing here says how either library performs on a real GPU.

No picture-parity claim

The same nominal lights gave a brighter Aura3D frame in the PBR viewer (mean luma 89.3 vs 55.0), so ports need exposure tuning.

No “less code to make a game” claim

A complete game with HUD, audio and replay was not compared line for line. The cold-start trial built one such game with Aura3D (n=1), as an existence proof.

Small samples

The bench is five scenes by one author. The cold-start trial is one model, five tasks, three runs each. Both found failures in our own docs, product and harness, which we fixed and listed.

Moving numbers

Bench timings are Aura3D 4.1.2; the frame-cost fixes cut the cube from 666 ms to about 50 ms but the other scenes were not re-run. Download and version counts are a snapshot.

Models are not people

Where we use a blind judge to compare looks, it is a model (claude-sonnet-5.5), not a human panel.

What we measured and how

Four sources, all in the repository.

Bench

Five scenes plus a one-cube baseline, each built as a standalone Vite app in both libraries and measured on a remote CPU runner at 640x360: lines, tokens, imports, bundle bytes, requests, time to first frame (median of 3), frame time (60 frames), draw calls, and luma-histogram divergence. tools/bench-vs-threejs/

Cold-start trial

Fresh agents with no repository context in isolated sandboxes: the Aura3D arm gets the packed library and the entry docs only, the three.js arm gets three.js types only. Same prompts, same model, 40-turn budget, scored remotely. tools/agent-eval/

Stock build

Packed tarballs installed into a fresh project, then a stock vite build and vite dev with no extra plugin, on Vite 7.3.2 and 7.3.7. evidence/stock-build/

Frame cost

Median milliseconds per frame, before and after each fix, on the same runner. evidence/perf-frame-cost/

Capability matrix

Sixty rows, each verified in code, taken from a document, or marked unknown, with a verdict of better, only, tie or unknown. docs/workflows/aura3d-vs-threejs-matrix.md

Migrating

The verified mapping for the 40 most common APIs and what the codemod cannot do: docs/migration/from-threejs.md.
