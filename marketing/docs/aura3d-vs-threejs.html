Everything three.js leaves to you, built in.

three.js gives you a renderer. Everything after that is your job: loaders, environment lighting, shadows, post-processing, controls, the game loop, the HUD, audio, asset handling, licensing and the deploy checks. Aura3D ships all of that as one engine and one toolchain, with its own renderer (WebGPU with a WebGL2 fallback, optionally in a worker), a typed declarative scene and an asset pipeline that will not let an unverified model reach production. It is built from the start to be written by AI coding agents.

three.js main.ts38 lines
import * as THREE from "three";
import { GLTFLoader } from "three/addons/loaders/GLTFLoader.js";
import { HDRLoader } from "three/addons/loaders/HDRLoader.js";

const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setPixelRatio(Math.min(devicePixelRatio, 2));
renderer.setSize(innerWidth, innerHeight);
renderer.toneMapping = THREE.NeutralToneMapping;
renderer.shadowMap.enabled = true;
document.querySelector("#app")!.appendChild(renderer.domElement);

const scene = new THREE.Scene();
scene.background = new THREE.Color("#2b2f36");
const camera = new THREE.PerspectiveCamera(35, innerWidth / innerHeight, 0.1, 100);
const pmrem = new THREE.PMREMGenerator(renderer);
new HDRLoader().load("/hdri/studio_small_08_1k.hdr", (hdr) => {
  scene.environment = pmrem.fromEquirectangular(hdr).texture;
  scene.environmentIntensity = 1.1;
  hdr.dispose();
});

const key = new THREE.DirectionalLight("#ffffff", 2.4);
key.position.set(6.52, 18.39, 13.98);
key.castShadow = true;
key.shadow.mapSize.set(2048, 2048);
scene.add(key);

new GLTFLoader().load("/aura-assets/product-fixture.glb", (gltf) => {
  gltf.scene.traverse((o) => { if ((o as THREE.Mesh).isMesh) o.castShadow = o.receiveShadow = true; });
  scene.add(gltf.scene);
  const box = new THREE.Box3().setFromObject(gltf.scene);
  const center = box.getCenter(new THREE.Vector3());
  const dist = box.getSize(new THREE.Vector3()).length() / (2 * Math.tan((camera.fov * Math.PI) / 360));
  camera.position.copy(center).add(new THREE.Vector3(0.5, 0.35, 1).normalize().multiplyScalar(dist));
  camera.lookAt(center);
});

addEventListener("resize", () => {
  camera.aspect = innerWidth / innerHeight;
  camera.updateProjectionMatrix();
  renderer.setSize(innerWidth, innerHeight);
});
renderer.setAnimationLoop(() => renderer.render(scene, camera));
Aura3D main.ts10 lines
import { camera, createAuraApp, interactions, looks, model, scene } from "@aura3d/engine";
import { assets } from "./aura-assets";

createAuraApp("#app", {
  scene: scene()
    .add(looks.preset("product-studio"))
    .add(model(assets.product, { name: "product", targetHeight: 1.6, castShadow: true }))
    .add(interactions.orbit({ target: "product" }))
    .camera(camera.frameAsset(assets.product, { targetHeight: 1.6 })),
  ...looks.appOptions("product-studio")
});

Eight reasons, each with the code behind it

Everything here shipped through 5.5.1. Each card names its source and the scope of the check behind it.

1. Typed scenes, typed assets

The CLI admits a model with its source, licence and sha256 and generates a typed key. A misspelt asset is a TypeScript error, not a 404, and in production an unverified model does not draw.

npx @aura3d/cli@latest assets resolve "robot" --name robot

scene().add(model(assets.robot, { targetHeight: 1.8 }))

templates/product-viewer/src/aura-assets.ts, docs/api/model-loader.md

2. WebGPU, with a WebGL2 fallback

One option. The same scene code runs on both backends, post effects included. All {{GAME_COUNT}} showcase games run on WebGPU by default; ?backend=webgl2 opts any of them out.

createAuraApp("#app", {
  scene,
  renderer: { backend: "auto" } // WebGPU first, WebGL2 fallback
});

Each game switched after a real-GPU check showed the same frame as WebGL2 and 0 errors (Apple M4 Max, headless Chrome). Without the option, the engine uses WebGL2. CHANGELOG.md 5.3.0 to 5.5.1, docs/upgrade-5.0.0/README.md

3. Rendering in a worker, opt-in

Move rendering off the main thread while game code keeps app.nodes, frame callbacks and picking. Unsupported calls throw a typed AuraWorkerError; diagnostics().fps counts worker frames.

import { createWorkerRendererWorker } from "@aura3d/engine/worker";

createAuraApp("#app", {
  scene,
  worker: {
    createWorker: createWorkerRendererWorker,
    fallback: "main-thread"
  }
});

All {{GAME_COUNT}} showcase games render in a worker with ?worker=1. Opt-in; physics and DOM labels stay with main-thread apps; no speed claim against the main thread. CHANGELOG.md 5.3.0, 5.5.0, 5.5.1

4. A good frame with no setup

A bare scene keeps its authored colours through a neutral output, metal and glass reflect a built-in studio room generated in code, lights.key casts a shadow by default and camera.auto frames the subject.

scene()
  .add(lights.key())                      // shadow on by default
  .add(primitives.plane({ name: "floor", size: [8, 1, 8] }))
  .add(primitives.sphere({
    name: "steel",
    material: material.pbr({ metallic: 1, roughness: 0.2 })
  }))
  .camera(camera.auto({ subject: "steel", fill: 0.6 }))

A requested fill of 0.8 measured 0.800 on a real GPU. CHANGELOG.md 5.3.0 (N1 to N4), evidence/n4-frame/

5. Tools for AI coding agents

Every new project gets llms.txt, 14 skills and compiled recipes. The CLI lets an agent look up the installed API, start from working code, lint and screenshot its own scene. Three.js names that models guess, such as material.standard or "aces-filmic", resolve; a name with a different meaning throws an error naming the Aura3D call.

aura3d info --name material.pbr
aura3d examples "gold product on a pedestal"
aura3d validate
aura3d render --json

docs/agents/agent-tools.md, docs/agents/guessable-api.md, packages/aura3d-cli/skills/

6. Bring your three.js work

aura3d import-three runs a three.js scene factory at build time and gives you a typed asset, an editable Aura3D scene and a report of what was carried, approximated or left out. three stays a dev dependency. For app code, aura3d migrate three writes an annotated port worklist.

npm i -D three
npx @aura3d/cli@latest import-three recipes/windmill.mjs

The bridge is a prototype and writes its report on every run. docs/agents/three-bridge.md

7. A deploy gate

check-deploy fails the build on a missing hashed asset, unreferenced files or asset-validation errors. --browser also loads every route in headless Chromium and fails on failed requests and console errors; --release adds licence and quality gates.

npx @aura3d/cli@latest check-deploy --dist dist --browser

Measured on the published package (benchmark run of 2026-10-28)

Facts about Aura3D alone, each from a benchmark target that passes. Software WebGL2 on a remote CPU runner, 640x360, one run. These are not GPU numbers.

First frame

A one-cube scene reaches its first frame in about 420 ms (median of 3 cold loads).

Draw calls

A one-cube scene draws in 1 call. A PBR viewer scene with a shadow and bloom draws in 25 (33 in the previous release).

Clean console

The five benchmark scenes log no console warnings or errors.

Options that work

Every option covered by the option-coverage test either takes effect or raises OPTION_IGNORED: 16 of 16 tests pass.

Targets that did not pass carry no claim; each is listed with its cause in evidence/vs-threejs/RESULTS-4.5.0.md.

What a library or two cannot add

These four parts only work because the engine, the CLI and the docs are built together.

Assets you can trust

Assets are typed, hashed and licensed end to end, and the renderer enforces it at run time. The CLI admits each model with its source and a hash, generates the typed key, and check-deploy fails the build when a hashed file is missing. In production the renderer refuses to draw an unverified model. If you ship AI-generated or third-party art, this is your licensing and supply-chain answer.

An engine agents can write

The API, docs, recipes and skills ship together and are tuned by a repeatable cold-start trial (tools/agent-eval). As we improved the docs, fresh agents working from the Aura3D docs alone went from 8 to 14 working scenes out of 15 and from 40 to 10 median turns, and every first build compiled (15 of 15). One model, 15 runs per arm.

The whole game stack

Fixed-step loop, seeded replay, QA hooks, safety net, high-refresh interpolation, HUD, touch, audio and genre kits come in one install, and {{GAME_COUNT}} shipped games exercise them.

Quality gates in the product

The public-example boundary test, route-health specs in all {{TEMPLATE_COUNT}} templates, assets validate --release and check-deploy come with the code. You get the release process along with the engine.

Migrating from three.js

aura3d migrate three maps 245 three.js constructs to Aura3D and writes an annotated port worklist for the rest, so you start from a list of changes instead of a blank file. For procedural content, aura3d import-three runs your three.js scene factory at build time and hands you a typed asset, an editable Aura3D scene and a report of what was carried (prototype; docs/agents/three-bridge.md). The porting guide covers the 40 most common APIs and what the codemod leaves to you: docs/migration/from-threejs.md.

How we measured

The benchmark builds five scenes (PBR viewer, forest, skinned character, game loop and water) as standalone Vite apps in both libraries and counts non-blank source lines, imports and API symbols, imports included. The product-shot comparison above is a separate check: the 10-line hero builds on a stock create-aura3d product-viewer project and renders, and the matched three.js app is 38 lines. Numbers are labelled “Aura3D benchmark, five scenes” wherever they appear; render checks ran on software WebGL2 on a CPU runner. The WebGPU and worker switches in the showcase games come from paired real-GPU runs per game (Apple M4 Max, headless Chrome), recorded in docs/upgrade-5.0.0/README.md; their frame-rate ratios decided each switch and are not performance claims. The scenes, scripts, results and frames are in evidence/vs-threejs, so you can rerun them.
