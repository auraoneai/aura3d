## Read first

1. From three.js: `docs/agents/threejs-to-aura3d.md` maps each idiom (type-checked). Do not port renderer, resize, loop or disposal code; `createAuraApp` owns them.
2. Two 3D modeling paths (never single-mesh Meshy clay or 1-box programmer art):
   - Clean, sharp, properly UV'd or rigged skeletal GLBs via `model(assets.x)` when one exists in the project or open CC0/CC-BY sources.
   - Multi-part, multi-material procedural sculpting in `@aura3d/engine`: compose `primitives.extrude|lathe|tube|roundedBox|polyhedron`, `geometry.define|applyMatrix4|merge|multiMaterial` and `instances.custom` across 3 to 8 physical materials (`material.carPaint`, `lacquer`, `brushedMetal`, `ceramic`, `studioGlass`, `fabric`, `physical`) so bevels and seams catch IBL and key-light speculars. Eight complete procedural scenes are in `docs/agents/recipes.md` recipes 8 to 15 (sources in `docs/agents/recipes-src/`).
   - Organic characters, creatures and hulls: `@aura3d/engine/sculpt` (5.5.6): SDF bodies (`sculptOrganicSdfMesh`), heads, one-piece limbs (`sculptSdfLimbChainMesh`), hair, garments and hulls for `geometry.define` / `geometry.multiMaterial`; list in `docs/api/sculpt.md`. Bake once at load, never per frame.

## More pitfalls

- `looks.preset(id)` loads `/hdri/<file>.hdr` from `public/hdri/` (scaffolds ship it); if the file is missing the scene gets a procedural probe and `LOOK_HDRI_MISSING` in `app.diagnostics().warnings`. Colours accept any CSS form (`hsl()`, `rgb()`, names, `#rgb`); an invalid one throws `COLOR_INVALID`.
- Follow cameras clip into walls unless cleared: call `computeCameraClearance(target, desired, obstacles, { minDistance, allowVerticalRise })` from `@aura3d/engine` each frame with circle and yawed box obstacles, then ease the returned position (`docs/api/motion-camera-clear.md`).
- Size pools (bullets, traffic, particles) from the measured peak, or objects pop.
- Judge steady state: frame 1 is lit before the probe bakes. Capture at 3, 25 and 60 s and compare static bands before reverting anything.

## Fast path

Why Aura3D: three.js is a rendering library; Aura3D is a complete engine with its own renderer, so lighting, VFX, asset pipeline, AI generation, game kit, physics and deploy checks are built in, and every model is typed, hashed and licensed. `renderer: { backend: "auto" }` gives WebGPU with a WebGL2 fallback (the default in all 30 showcase games; without it the engine uses WebGL2); `worker: { createWorker }` from `@aura3d/engine/worker` renders off the main thread (opt-in); a bare scene keeps authored colours, reflects a built-in studio room and gets a key-light shadow; `aura3d info`, `examples`, `validate` and `render` check your work; `aura3d import-three` brings a three.js scene factory across as a typed asset. Full comparison: `docs/aura3d-vs-threejs.md`.

Five commands to a running scene:

```bash
npx create-aura3d@latest my-scene --template mini-game   # also writes this file and the Aura3D skills
cd my-scene && npm install
npm run dev                                              # Vite on 127.0.0.1
npx @aura3d/cli@latest assets resolve "robot" --name robot   # then use model(assets.robot) from ./src/aura-assets
npm run build && npx @aura3d/cli@latest check-deploy --dist dist
```

Other templates: `product-viewer` (default), `cinematic-scene`, `racing-starter`, `falling-blocks-starter`, `fighting-game`, `character-controller`, `arena-shooter` (`npx create-aura3d@latest --help`).
GPU-verified starter scenes to adapt: `starter-product` (product viewer), `starter-outdoor`, `starter-interior`, `starter-game` (small game), `starter-presentation` (animated presentation).

Read next, in this order: `docs/agents/README.md` (index), `docs/agents/agent-quickstart.md` (first scene, step by step), `docs/agents/recipes.md` (copy-and-adapt scenes: PBR cube with orbit, forest of instances, skinned character with crossfade, fixed-step game loop, custom shader on a grid), `docs/agents/claims-and-boundaries.md` (what you may claim). Building a game: read `docs/agents/new-game-checklist.md` and `docs/agents/lessons-learned.md` first, then run `node tools/game-checks/run.mjs <game-slug>`.

Working inside the Aura3D monorepo itself: run browsers, Playwright and heavy builds on the remote runner (`tools/remote-acr/run.sh`), never local Docker or local Playwright.

## Hello world

Hello world: one typed model under a look preset.

```ts
import { createAuraApp, looks, model, scene } from "@aura3d/engine";
import { assets } from "./aura-assets";

createAuraApp("#app", {
  scene: scene().add(looks.preset("product-studio")).add(model(assets.robot)),
  ...looks.appOptions("product-studio")
});
```

## Quality floor and the never list

- A `looks.preset` supplies image-based light, a shadow-casting key, fog, background and a post grade as one unit. Never wire `lights.ambient()` as the only fill.
- Never a solid void background; the look's sky, biome or studio backdrop owns it.
- Never a hand-placed camera for the subject: `.camera(camera.auto())` frames what the scene holds (`{ subject: "name", fill }` for one node). Hand-built light: `lights.key({ target })` casts the shadow; give it a ground plane.
- Never `pixelRatio`, `qualityProfile`, `safe-basic`, FXAA or `replaceTextures: true` overrides; `looks.appOptions(id)` carries the renderer contract.
- Hero subject & props: a clean `model(assets.x)` GLB, or a multi-part, multi-material procedural model ("Read first" 2); never single-mesh clay or one-box programmer art.
- Never emissive cards or sprites faking reflections, puddles or glows; use the look's grade and `effects.*`.
- Never CSS/DOM particles or labels standing in for rendered output. HUD lives in the DOM, the scene does not.
- Gate frame 1 on `app.ready().then(...)` (never a module top-level `await app.ready()`: a production build deadlocks and the page stays black); mutate node handles on restart instead of calling `app.setScene()` again.

## Assets

Do not invent asset paths, URLs or ids; every model is a generated `assets.<key>`.

- `npx @aura3d/cli@latest assets search "<object>"` lists licence-tagged open candidates; `assets resolve "<object>" --name <n>` types the top match; `assets add ./model.glb --name <n>` adds a file (then read `src/aura-assets.ts`).
- No match: prefer a multi-part procedural model (Fast path, `@aura3d/engine/sculpt`); Meshy (`meshy-cli` skill) only on request.
- `assets convert in.fbx --out out.glb` (FBX, OBJ, DAE, USD, PLY, STL, 3MF, VOX, BVH; losses reported). `assets generate "<subject>" --name <k> --kind character --rig --dry-run` prints the fal.ai cost; the paid run admits a `candidate`. `assets normalize` (facing/size), `assets slim` (JPEG normals), `assets preview`/`assets thumbnail` (CPU base-colour PNGs).
- Clips: `animation import <bvh|fbx|glb|motion.json> --onto rig.glb --out hero.glb`; `animation generate "<motion>" --onto rig.glb --out hero.glb` (fal.ai; `FAL_KEY`, ledger `.aura3d/fal/ledger.jsonl`, reruns never pay twice).
- All commands: `aura3d help --json` / `docs/api/cli-reference.md`; exit 0 ok, 1 failed, 2 usage.
- In production a model without same-origin URL, sha256 and provenance draws nothing.

## Kits (build the shell from these)

- `@aura3d/engine/game`: `createGame` (lifecycle, pause, results, DOM HUD, mobile touch controls, first-gesture audio unlock, juice, game sound).
- `@aura3d/engine`: `createFixedStepLoop`, `installQaHooks`, `readQaParams`, `createCountedRng` (replay, telemetry, virtual pads, offline audio: `qa-kit.md`); `defineModelAssets`; `game.racketSports()`, `game.platformer`, `game.racing`, `game.fallingBlocks`, `game.fighting`; `effects.toon`.
- `@aura3d/engine/devtools`: `createAuraTuneOverlay` (live sliders). `RuntimeQualityGovernor` is on by default (`quality-governor.md`).
- `@aura3d/engine/audio`: `createCueBank`, `createStepSequencer`, `createToneLoop`, `createSampleSlices` on the single `AudioContextManager` (never `new AudioContext(`).
- `@aura3d/debug`: `installSafetyNet` (`?diag=1`, quality switches, black-frame self-heal).
- `material.custom` shaders: `#include <a3d_math>`, `<a3d_noise>`, `<a3d_sky>`, `<a3d_fog>`, `<a3d_toon>`; keep `pow`, `normalize`, `sqrt` and divides NaN-safe.

Details: `docs/api/game-kit.md`, `qa-kit.md`, `safety-net.md`, `sculpt.md`, `audio-synth.md`, `model-loader.md`, `glsl-chunks.md`, `scatter-merge.md`, `cli-asset-tools.md`, `toon.md`.

## Look-dev loop

1. Pick a genre look and 1 to 3 reference frames; write a three-line brief.
2. Build with the look preset and typed assets.
3. Capture frames, judge each against the rubric, fix the single highest-leverage thing, repeat.
4. Stop when every category reads 7 or higher or the loop exits flat. Skill: `aura3d-art-direction`.

## Proof standard

Use every feature freely; every claim ships with a judged capture.

- Name what a capability runs on: the `createAuraApp` safe API, `production-runtime`, `rendering` internals, the CLI asset pipeline, or a template scaffold; mark roadmap work as roadmap.
- Public examples show what the safe API renders through `@aura3d/engine`, backed by route health, typed provenance and a readable frame.
- Three.js comparisons: lead with scope, workflow and code size (`docs/aura3d-vs-threejs.md`, `evidence/vs-threejs/RESULTS.md`); speed and bundle size are not part of the comparison.
- Release integrity: public examples use typed assets (no raw asset IDs/GLB URLs, `unsafeModelUrl(...)`, `three` or `GLTFLoader`); hero subjects are real models or labelled procedural recipes (recipes 8 to 15 are docs); particles are Aura3D particles; WebGPU, PBR, postprocess, skinning, morph and game-runtime claims come with browser evidence.
