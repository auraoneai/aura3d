# Aura3D

> Aura3D {{VERSION}}: a TypeScript SDK for browser 3D apps and games. You write a typed, declarative scene with `@aura3d/engine`; the `@aura3d/cli` toolchain handles typed GLB/glTF assets, checks and deploy gates. Built to be driven by AI coding agents. Site: {{ORIGIN}}

## Start here: four steps, then stop

1. Start from working code: `aura3d examples "<what you are building>"` prints a complete, runnable `src/main.ts` for the closest scene (product viewer, character, portal or effect, outdoor, interior, small game, materials, presentation) and its setup. Save it with `aura3d examples --id <id> --write src/main.ts --force`, then change names, colours and numbers. Do not write a scene from memory or read `node_modules`.
2. `aura3d validate` (about a second) and fix what it reports.
3. `aura3d render` once. It prints a short text summary: subject framing (`framed`, `small`, `cropped`, `off-centre`), exposure, shadow, motion, errors, fps and `next`. Add `--screenshot` only when you must see the pixels; an image costs far more context than the summary.
4. Done rule: when `aura3d validate` passes and one `aura3d render` says `done` (subject framed, exposure ok, no errors), stop and finish. Do not keep polishing: another tweak-and-render pass costs a turn and rarely changes the verdict. Outside a scaffold, `aura3d` is `npx @aura3d/cli@latest`.

## Exact signatures (the calls agents look up most; no `aura3d info` needed for these)

Options are optional unless shown bare; vectors `[x, y, z]`, colours CSS strings, angles radians. Every line is type-checked in `docs/agents/recipes-src/llms-signatures.check.ts`.

- `createAuraApp("#app", { scene, ...looks.appOptions(id) })`; `app.onFrame((f) => ...)` gives `f.dt`, `f.time` in seconds; `void app.ready()`; `app.pause()`, `app.resume()`.
- `scene({ background })` `.add(node)` `.camera(spec)`. Any node builder: `.position(x, y, z)`, `.rotation(x, y, z)`, `.scale(s)` or `.scale([x, y, z])` (one argument), `.lookAt(x, y, z)`, `.runtime({ id, mutable: true })` (required before any runtime change).
- `group(name, [children], { position, rotation, scale })`: name first, children an array.
- `primitives.box|sphere|cylinder|cone|capsule|plane|torus|torusKnot|ring|circle|roundedBox({ name, size, material, castShadow, receiveShadow, params })`: `size` is a number or `[x, y, z]`; plane `[w, 1, d]`.
- `instances.box|sphere|cylinder|cone({ name, transforms: [{ position, rotation, scale }], colors, material })`.
- `lines.loop({ points: [[x, y, z], ...], colors })` (closed), `lines.line({ points })` (open).
- Handle `const h = app.nodes.require(id)` (`app.nodes.get(id)` may be undefined): `h.setPosition(x, y, z)`, `h.setRotation(x, y, z)`, `h.translate(x, y, z)` take three numbers; `h.setScale(s)` or `h.setScale([x, y, z])` takes one (`setScale(x, y, z)` is TS2554).
- `h.setVisible(b)`, `h.setMaterial(material.pbr({ ... }))`, `h.setColor?.(css)`, `h.setEmissive?.(css, intensity)`, `h.setOpacity?.(a)`; lights `h.setLight?.({ color, intensity, distance }, { transitionSeconds })`, `h.setIntensity?.(v)`; `h.setInstances(transforms, colors)`; `h.setUniform?.(name, value)`; `h.play(clip, { loop, crossFade })`. There is no `h.materials`, `h.timeScale` or `h.animation`.
- `camera.auto({ subject, fill: 0.6, angle: "three-quarter" | "front" | "side" | "top", elevation, azimuth })`; `camera.orbit({ position, target, fov })` with `interactions.orbit({ target: "<node name>" })`; `camera.perspective({ position, target, fov })`; `camera.flythrough({ position, target, fov, from, to })`.
- Move the camera: `app.camera?.setPose({ position, target, fov }, { cut: true })` (`app.camera` is optional, always `?.`); a framed pose for a box: `camera.framePose({ min, max }, { fill, azimuth, aspect })`.
- `looks.preset(id, { exposureEv, background, accent })` plus `...looks.appOptions(id)`; `environments.neutral({ intensity, background: false })` (metals need it), `environments.studio({ preset: "studio" | "softbox", intensity })`.
- `lights.key({ target, intensity, color, shadow })` (shadowed directional), `lights.directional({ position, target, intensity, color, shadow })`, `lights.point({ position, intensity, color, distance, decay })`, `lights.rect|softbox({ position, target, width, height, intensity })`, `lights.ambient({ intensity, color })`, `lights.hemisphere({ skyColor, groundColor, intensity })`.
- `material.pbr({ color, metallic, roughness, emissive, emissiveIntensity, opacity, doubleSided })`; `material.physical({ ...those, clearcoat, clearcoatRoughness, sheen, transmission, ior, thickness })`; `material.carPaint|chrome|glass|ceramic|fabric({ color })`; `material.emissive({ color, emissive, emissiveIntensity })`.
- `material.custom({ glsl: { vertex, fragment }, uniforms: { clk: { type: "f32", value: 0 } }, transparent })`, then `h.setUniform?.("clk", f.time)` every frame. `texture.data({ width, height, data, format: "rgba8" })`, `texture.canvas({ canvas })`.
- `effects.bloom({ intensity, threshold, radius })`; `effects.particles({ name, position, rate, maxParticles, lifetime: [a, b], speed: [a, b], size: [a, b], color, gravity, drag, blend: "additive" | "alpha", seed })`; `effects.fog({ mode: "exp2" | "linear" | "height", color, density })`, at runtime `app.atmosphere?.setFog({ ... })`; `sky.gradient({ zenith, horizon, ground })`. Time scale: `if (app.time) app.time.scale = 0.5`.

## Read first

1. Coming from three.js? `docs/agents/threejs-to-aura3d.md` maps each three.js idiom to the Aura3D line (every line type-checked). Do not port renderer, resize, loop or disposal code: `createAuraApp` owns them.
2. No model admitted yet? Build it procedurally from `primitives.*`, `geometry.define`, `instances.*`, `material.*` and `environments.neutral`. Eight complete scenes are `docs/agents/recipes.md` recipes 8 to 15 (sources in `docs/agents/recipes-src/`); recipe 17 is a materials board.

## More pitfalls

- `looks.preset(id)` loads `/hdri/<file>.hdr` from `public/hdri/` (scaffolds ship it); if the file is missing the scene gets a procedural probe and `LOOK_HDRI_MISSING` in `app.diagnostics().warnings`. Colours accept any CSS form (`hsl()`, `rgb()`, names, `#rgb`); an invalid one throws `COLOR_INVALID`.
- Pools (bullets, traffic, particles) must be sized from the simulation's measured peak, or objects pop in and out.
- Judge steady state: the first frame is lit differently from the baked probe seconds later. Capture at 3, 25 and 60 s; animated scenes flip between captures, so compare static bands before reverting anything.

## Fast path (read this first)

Why pick it over three.js: Aura3D is a standalone TypeScript engine with its own renderer, so lighting, asset pipeline, game kit and deploy checks are built in, and every model is typed, hashed and licensed. `renderer: { backend: "auto" }` gives WebGPU with a WebGL2 fallback (the default in all 30 showcase games; without it the engine uses WebGL2); `worker: { createWorker }` from `@aura3d/engine/worker` renders off the main thread (opt-in); a bare scene keeps authored colours, reflects a built-in studio room and gets a key-light shadow; `aura3d info`, `examples`, `validate` and `render` check your work; `aura3d import-three` brings a three.js scene factory across as a typed asset (prototype). Full list with sources: `docs/aura3d-vs-threejs.md`. Comparison numbers: `evidence/vs-threejs/RESULTS.md` only.

Five commands to a running scene:

```bash
npx create-aura3d@latest my-scene --template mini-game   # also writes this file and the Aura3D skills
cd my-scene && npm install
npm run dev                                              # Vite on 127.0.0.1
npx @aura3d/cli@latest assets resolve "robot" --name robot   # then use model(assets.robot) from ./src/aura-assets
npm run build && npx @aura3d/cli@latest check-deploy --dist dist
```

Other templates: `product-viewer` (default), `cinematic-scene`, `racing-starter`, `falling-blocks-starter`, `fighting-game`, `character-controller`, `arena-shooter` (`npx create-aura3d@latest --help`).
GPU-verified starter scenes to adapt: `starter-product` (product viewer), `starter-outdoor`, `starter-interior`, `starter-game` (small game), `starter-presentation` (animated presentation).

Read next, in this order: `docs/agents/README.md` (index), `docs/agents/agent-quickstart.md` (first scene, step by step), `docs/agents/recipes.md` (copy-and-adapt scenes: PBR cube with orbit, forest of instances, skinned character with crossfade, fixed-step game loop, custom shader on a grid), `docs/agents/claims-and-boundaries.md` (what you may claim). Building a game: read `docs/agents/new-game-checklist.md` and `docs/agents/lessons-learned.md` first, then run `node tools/game-checks/run.mjs <game-slug>`.

Working inside the Aura3D monorepo itself: run browsers, Playwright and heavy builds on the remote runner (`tools/remote-acr/run.sh`), never local Docker or local Playwright.

## Hello world

Hello world: one typed model under a look preset.

```ts
import { createAuraApp, looks, model, scene } from "@aura3d/engine";
import { assets } from "./aura-assets";

createAuraApp("#app", {
  scene: scene().add(looks.preset("product-studio")).add(model(assets.robot)),
  ...looks.appOptions("product-studio")
});
```

## Quality floor and the never list

- A `looks.preset` supplies image-based light, a shadow-casting key, fog, background and a post grade as one unit. Never wire `lights.ambient()` as the only fill.
- Never a solid void background; the look's sky, biome or studio backdrop owns it.
- Never a hand-placed camera for the subject: `.camera(camera.auto())` frames what the scene holds (`{ subject: "name", fill }` for one node). Hand-built light: `lights.key({ target })` casts the shadow; give it a ground plane.
- Never `pixelRatio`, `qualityProfile`, `safe-basic`, FXAA or `replaceTextures: true` overrides; `looks.appOptions(id)` carries the renderer contract.
- Hero subject: use `model(assets.x)` with a typed asset when one exists or the prompt names a real object. With no admitted model (a world, a creature, a prop set, an abstract piece) build it procedurally as in recipes 8 to 15, never as a flat placeholder.
- Never emissive cards or sprites faking reflections, puddles or glows; use the look's grade and `effects.*`.
- Never CSS/DOM particles or labels standing in for rendered output. HUD lives in the DOM, the scene does not.
- Gate frame 1 on `app.ready().then(...)` (never a module top-level `await app.ready()`: a production build deadlocks and the page stays black); mutate node handles on restart instead of calling `app.setScene()` again.

## Porting three.js

Porting existing three.js code: `aura3d migrate three` and the `aura3d-threejs-migration` skill record every approximation; the codemod is not a drop-in claim.

## Assets

Never invent asset paths, URLs or ids. Every model comes from a generated `assets.<key>`.

- `npx @aura3d/cli@latest assets search "<object>"` searches licence-tagged open public sources and a starter pack; results are candidates to check, and there is no Aura3D-run search service to rely on.
- `assets resolve "<object>" --name <name>` pulls the top match and types it as `assets.<name>`.
- `assets add ./assets/model.glb --name model` adds a local file; then read the generated `src/aura-assets.ts`.
- No catalog match: generate with Meshy (`meshy-cli` skill), optimize (`assets optimize --file in.glb --out out.glb --role <role>`), then admit (`assets import-meshy`).
- Production needs every model to have a same-origin URL, a 64-character sha256 and provenance, otherwise it draws nothing.

## Kits (build the shell from these)

- `@aura3d/engine/game`: `createGame` (lifecycle, pause, results, DOM HUD, touch, juice, game sound).
- `@aura3d/engine`: `createFixedStepLoop`, `installQaHooks`, `readQaParams`, `createCountedRng` (deterministic replay); `defineModelAssets`; `game.racketSports()`, `game.platformer`, `game.racing`, `game.fallingBlocks`, `game.fighting`; `effects.toon`.
- `@aura3d/engine/audio`: `createCueBank`, `createStepSequencer`, `createToneLoop`, `createSampleSlices` on the single `AudioContextManager` (never `new AudioContext(`).
- `@aura3d/debug`: `installSafetyNet` (`?diag=1`, quality switches, black-frame self-heal).
- `material.custom` shaders: `#include <a3d_math>`, `<a3d_noise>`, `<a3d_sky>`, `<a3d_fog>`, `<a3d_toon>`; keep `pow`, `normalize`, `sqrt` and divides NaN-safe.

Details: `docs/api/game-kit.md`, `qa-kit.md`, `safety-net.md`, `audio-synth.md`, `model-loader.md`, `glsl-chunks.md`, `scatter-merge.md`, `cli-asset-tools.md`, `toon.md`.

## Look-dev loop

1. Pick a genre look and 1 to 3 reference frames; write a three-line brief.
2. Build with the look preset and typed assets.
3. Capture frames, judge each against the rubric, fix the single highest-leverage thing, repeat.
4. Stop when every category reads 7 or higher or the loop exits flat. Skill: `aura3d-art-direction`.

## Claims

Use every feature freely. Claim only what a judged capture shows.

- Label every capability as one of: `createAuraApp` root safe API, `production-runtime`, `rendering` internals, CLI asset pipeline, template-only scaffold, prototype, or roadmap.
- Public examples prove only what the safe API renders through `@aura3d/engine`.
- A compiling route is not proof: route health, typed provenance and a readable frame are required.
- Comparison numbers against three.js exist only in `evidence/vs-threejs/RESULTS.md`: software WebGL2, one author, five small scenes. They are not GPU results and not a general "less code" or "faster" claim.

Release integrity rules:
- no raw string asset IDs, raw GLB/glTF URLs, `unsafeModelUrl(...)`, `three` imports, or `GLTFLoader` in public examples;
- no primary character, vehicle, product, weapon, creature, world, or hero environment made only from primitives unless the route is explicitly abstract visualization or a labelled procedural recipe (recipes 8 to 15 are docs recipes, not showcase claims);
- no CSS/DOM particle implementation for examples claiming Aura3D particle rendering;
- no WebGPU, PBR, postprocess, skinned animation, morph, or game-runtime claim without matching browser evidence;
- no public showcase or README claim that exceeds detected capability, route-health evidence, or screenshots.
