# Turbo Drift Circuit

Status: materially rebuilt (single-path); independent exact-artifact review pending

Claim label: createAuraApp

Primary assets: `carModel` (`showcaseCleanSportsCar.1c69283f.glb`) and
`trackModel` (`showcaseReadableKartCircuit.5cbb912e.glb`)

Turbo Drift Circuit is a three-lap arcade racing route with six ordered
checkpoints, a typed player sports car, an AI rival driven through the shared
engine driver, a time-trial ghost car, deterministic straight-line boost pads,
a chase camera rig (`looks.preset("golden-hour")`, FOV 60), and per-wheel
mesh-backed surface grounding. A single code path (`src/main.ts`) boots at
every URL; the former `src/legacy` / `src/v2` dispatcher and generated
`src/generated/game-geometry.ts` contract are deleted.

## Single-Path Architecture

| Module | Responsibility |
| --- | --- |
| `src/main.ts` | Single-path entry mounted via `createGame` (`@aura3d/engine/game`), wiring `game.racing` kits, `createVehicleChassis` over `meshVehicleSurface(trackMeshQuery)`, `motorsport` HUD widgets (`speed`, `lap`, `race-position`, `objective`), `steer-pedals` touch preset, `sfxUrl` audio cues, juice feedback, and `window.__aura3dGameSnapshot` evidence. |
| `src/track-surface.ts` | Generated by `scripts/extract-track-surface.mjs` from the shipped `trackModel` and `carModel` GLBs; exposes `trackMeshQuery` (`createMeshSurfaceQuery`), `sampleTrackAt`, `CAR_MODEL_SIZE`, and `CAR_MODEL_MIN_Y` so the exact rendered track mesh grounds all four wheels. |
| `src/feel.ts` | Start-lights countdown state machine (`3 -> 2 -> 1 -> GO`), jump-start penalty detection, HUD status resolution (`Lights` / `Racing` / `Finished` / `Paused`), and progress-gap formatting. |
| `src/ghost.ts` | Deterministic time-trial lap recorder, FNV-1a path hashing, JSON round-trip serialization, and visual-only ghost car interpolation (`createTurboGhostRecorder`, `createTurboGhostPlayer`). |
| `src/boost-rings.ts` | Curvature-sampled straight-line boost pad planner (`planTurboBoostRings`) and per-lap boost burst state (`createTurboBoostState`, `collectTurboBoostRing`, `updateTurboBoost`). |
| `src/opponent-ai.ts` | Rival state container (`createTurboOpponentAi`) delegating steering and corner-speed decisions to the shared engine `createVehicleDriverAi` with late-race inside-line defense and yield offsets. |
| `src/passing-lane.ts` | Road-width, visual-asphalt corridor, side-by-side passing clearance, and rival yield/defense offset math (`measureTurboPassingLane`, `decideTurboOpponentYield`). |

## Controls

- `W` / `ArrowUp`: throttle
- `S` / `ArrowDown`: brake
- `A` / `ArrowLeft`: steer left
- `D` / `ArrowRight`: steer right
- `Space`: drift
- `ShiftLeft` / `ShiftRight`: boost
- `G`: toggle the time-trial ghost replay (once a lap is recorded)
- `R`: reset race

## Grounding & Evidence

No rendered Y in `src/main.ts` is a route-local surface constant, and there is
no additive surface lift (`ROAD_DETAIL_SURFACE_LIFT`, `TRACK_SURFACE_Y`, etc.
are deleted). Both player and opponent cars step `createVehicleChassis` over
`meshVehicleSurface(trackMeshQuery)` and seat their world-mode GLB nodes with
`groundedFittedModelPosition(pose, CAR_MODEL_SIZE)` minus `CAR_MODEL_MIN_Y`.
Per-wheel `groundClearance` is published every frame on
`window.__aura3dGameSnapshot` and verified across a full driven lap sweep in
`tests/qr/prd14/turbo-drift/grounding.test.ts`.

## API gaps refused

This route avoids renderer-library imports, direct GLB loader internals, and
bespoke renderer loops. Gameplay uses the public `@aura3d/engine` and
`@aura3d/engine/game` surfaces (`createGame`, `game.racing`,
`createVehicleChassis`, `createVehicleDriverAi`, `meshVehicleSurface`)
throughout; no physical tyre model, drivetrain, or motorsport simulation is
claimed. Label remains `createAuraApp` / prototype-blocked.
