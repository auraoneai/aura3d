# Migrating to Aura3D 2.0

Version: 2.0.0

Status: release-candidate migration guide; publication pending

Aura3D 2.0 changes the supported public presentation and ownership model. It
does not mean every internal renderer or historical example became a root-API
feature. Migrate against the package and claim boundary you actually use.

## Package version

After 2.0 is published, pin the release explicitly while validating:

```bash
npm install @aura3d/engine@2.0.0
npx create-aura3d@2.0.0 my-app --template product-viewer
```

Do not use these commands as proof of availability before npm publication is
verified.

## Public authoring path

For agent-authored and public application code:

- import from `@aura3d/engine` or a documented exported subpath;
- add GLB/glTF assets through `@aura3d/cli` and import generated `assets.*`
  entries;
- avoid package source deep imports, raw loaders, raw model URLs, and guessed
  asset IDs;
- treat `@aura3d/rendering` as a lower-level package boundary, not automatic
  proof that the safe root API exposes the same operation.

For smaller new applications, prefer the workload entry instead of the broad
compatibility root:

| Workload | Recommended 2.0 import |
| --- | --- |
| Lean scene | `@aura3d/lean` |
| Typed product/glTF viewer | `@aura3d/lean/product` |
| Deterministic non-physical arcade route | `@aura3d/lean/game` |
| Optional rigid-body simulation | `@aura3d/physics` plus `@aura3d/physics-rapier` |
| Optional navigation/crowds | `@aura3d/navigation-recast` |

The former `@aura3d/engine/lean`, `/lean-product`, and `/lean-game` specifiers
remain deprecated compatibility aliases in 2.0. They are not the recommended
new-app entries.

## Automated specifier migration

Run the checked-in codemod against application source, inspect its diff, then
install the destination packages it names:

```bash
pnpm migrate:2.0 --dry-run ./src
pnpm migrate:2.0 ./src
```

It performs exact quoted-specifier rewrites only:

```text
@aura3d/engine/lean          -> @aura3d/lean
@aura3d/engine/lean-product  -> @aura3d/lean/product
@aura3d/engine/lean-game     -> @aura3d/lean/game
@aura3d/engine/ecs           -> @aura3d/ecs
@aura3d/engine/scripting     -> @aura3d/scripting
```

It deliberately does not rewrite physics, navigation, or removed route logic:
those changes alter semantics and require a developer decision.

## Physical simulation and navigation breaks

Aura3D 2.0 replaces duplicate/custom commodity ownership rather than carrying
multiple production implementations indefinitely:

- Rapier (`@dimforge/rapier3d-compat@0.20.0`) is the sole selected physical
  simulation owner behind the optional Aura3D adapter. The old `"aura-js"` and
  `"cannon-es"` backend values now fail with migration guidance.
- The 1.5.2 `CharacterController`, `Navigation`, `Steering`, `Crowd`,
  `VehicleDynamics`, `NarrowPhase`, `PlatformerFixtures`,
  `PhysicsSandboxFixtures`, `ClothFixtures`, `SoftBodyFixtures`,
  `FractureFixtures`, `FluidFixtures`, and `FireSmokeFixtures` physics-barrel
  modules are removed in 2.0.
- Physical character movement uses the lazily initialized
  `@aura3d/physics-rapier` character controller. Authored-unit gameplay uses
  the public arcade/kinematic helpers and must not be described as physical
  simulation.
- Navigation, 3D path queries, crowds, tile caches, and temporary obstacles
  move to the optional `@aura3d/navigation-recast` adapter. The old grid and
  steering APIs are not aliased because their coordinate system and behavior
  differ materially.

The complete replacement tables and runnable examples are in
`docs/migration/physics-rapier-2.0.md` and
`docs/migration/navigation-recast-2.0.md`.

## Descriptor, evidence-fixture, and fabricated compatibility removal

Aura3D 1.5.2 published several families of objects that described a capability
without executing it: `*Fixture`, `*Evidence`, and `*Telemetry` sample-data
generators; `ThreeCompat*` renderer/material/environment descriptor facades;
GLTF scene-analysis evidence objects; production-environment inventory
descriptors; and duplicate audio effect preset wrappers. Aura3D 2.0 removes
those public runtime exports. They have no compatibility adapter because an
adapter would preserve the false implication that calling them performs the
named runtime behavior.

The removed `@aura3d/three-compat/postprocessing` subpath is part of the same
correction. Its composer and passes did not own a GPU device or issue draw
calls. The Three.js migration utility now leaves official postprocessing
imports intact and emits an actionable `postprocessing-unsupported` warning
that points developers to the real, separately scoped Aura3D effects API.

Consumers must replace sample-data generators with application-owned test
fixtures, use the real owning runtime API where one is documented, or remove
the associated capability claim. The exhaustive package/subpath/runtime/type
symbol list and its classification are generated by
`pnpm check:public-surface-diff` into
`docs/project/public-surface-diff-2.0.md` and
`tests/reports/public-surface-diff.json`. Any future removal that does not match
one of these explicit 2.0 categories fails that gate as unclassified.

## Node media relocation

FFmpeg frame encoding, PNG-sequence encoding, audio muxing, caption-file
export, publishing-package construction, and YouTube upload helpers are no
longer exported through the browser-safe root, `./engine`, or
`./engine-runtime` barrels. Their complete retained runtime/type surface moves
to `@aura3d/engine/media-node`. This is an intentional environment-boundary
relocation: Node consumers change only the import specifier; browser consumers
must not bundle these filesystem, process, encoder, or publishing owners.
`pnpm check:public-surface-diff` verifies every relocated 1.5.2 symbol exists on
the new subpath before classifying it as relocated.

## Consolidated public hosts

Several duplicate or diagnostic-only example hosts are no longer public. This
does not necessarily remove the underlying implementation or test contract.
If an integration depended on an example URL, migrate to the retained owner:

| Previous public-host category | 2.0 owner |
| --- | --- |
| duplicate character viewers | `examples/character-animation-viewer` or Animation Studio Pro |
| duplicate material studios | `examples/material-showroom` |
| duplicate product configurators | `examples/product-configurator` |
| broad physics sandbox | `examples/raycast-ccd-lab` for bounded query evidence |
| shadow/HDR/WebGPU contract pages | internal browser fixtures and package-level evidence |
| fake editor-output/game/racing pages | no public replacement until real quality and mechanic gates pass |

Do not preserve removed hosts merely to keep a misleading URL alive. If your
application used code from one, depend on its owning exported package API or
copy the app-specific source under your own application boundary.

## Visual and claim changes

2.0 requires claim labels to match evidence. A renderer stress harness is not a
large-world game; an LDR postprocess audit is not a production compositor; a
CPU particle diagnostic is not GPU particle proof; an unsupported WebGPU
capability receipt is not a rendered WebGPU feature. Update product copy and
tests accordingly.

## Breaking-change checklist

- [ ] Replace source/deep imports with exported package paths.
- [ ] Replace raw or string model references with generated typed assets.
- [ ] Replace links to internalized example hosts with the retained owner or an
      application-owned route.
- [ ] Revalidate rendering-package consumers separately from root-API apps.
- [ ] Re-run browser screenshots; 2.0 intentionally changes framing and visual
      output for several retained diagnostics.
- [ ] Remove claims inherited from historical `three@0.165.0` reports unless
      the corresponding current `three@0.185.1` row passes.
- [ ] Verify the exact npm package version and tarball after publication before
      deploying production consumers.

## Deprecation and removal schedule

Aura3D does not leave compatibility debt on an unspecified timeline:

| Surface | 2.0 status | Earliest removal |
| --- | --- | --- |
| `@aura3d/engine/lean*` aliases | deprecated; codemod available | 3.0, not before 2027-08-11 |
| `@aura3d/engine/ecs` and `/scripting` aliases | deprecated; codemod available | 3.0, not before 2027-08-11 |
| standalone `@aura3d/three-compat` migration package | supported throughout 2.x | reviewed for 3.0, not before 2027-08-11 |
| removed 1.5.2 physics/navigation modules | removed with semantic replacements documented above | removed in 2.0.0 |
| internalized duplicate/diagnostic example hosts | not a supported package API; retained evidence is archived | removed from the 2.0 public route inventory |

Removal in 3.0 still requires a fresh public-surface diff, packed consumer
tests, migration evidence, and a release note. This date is a floor, not a
promise to remove a still-used adapter.

Earlier migration drafts were consolidated into this major-version matrix and
removed from the current documentation surface. Git history remains the archive.
